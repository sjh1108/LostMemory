# CL-055 Boss Clear Result Flow 구현 현황

## 목적

보스 처치 후 바로 결과창으로 전환하지 않고, 보스 클리어 포탈을 통해 다음 흐름으로 진입하도록 연결한다.

목표 흐름은 다음과 같다.

```text
Boss defeated
  -> Boss room RoomCleared
  -> Boss clear portal shown
  -> Player interacts with portal
  -> if next stage exists: build next stage
  -> else: show run result panel
```

## 구현 상태

상태: 구현 진행 완료, Unity Play Mode 최종 확인 필요

현재 코드 기준으로 보스 클리어 후 포탈을 띄우고, 포탈 상호작용을 통해 `RunManager`가 다음 스테이지 또는 결과창 흐름을 결정하는 구조가 들어가 있다.

## 주요 변경 사항

### RunManager

파일: `Assets/_Project/Scripts/Runtime/Stage/RunManager.cs`

- 보스방 `RoomCleared` 수신 시 즉시 `RunCleared`로 전환하지 않도록 변경했다.
- 보스방 클리어 시 `bossClearPortalReady`를 켜고 포탈 진입을 대기한다.
- `NotifyBossClearPortalEntered()`를 추가했다.
  - 현재 상태가 `InRun`인지 확인한다.
  - 보스방 클리어 이후 포탈 사용인지 확인한다.
  - 다음 스테이지가 있으면 다음 스테이지 빌드로 진행한다.
  - 다음 스테이지가 없으면 `RunCleared -> Resulting -> RunResultPanelView.Show(data)` 흐름으로 진행한다.
- `totalStageCount`, `CurrentStageIndex`, `HasNextStage`를 추가했다.
- 플레이어 패배 또는 결과창 닫기 시 포탈 대기 상태를 정리하도록 했다.

### RunStateMachine

파일: `Assets/_Project/Scripts/Runtime/Stage/RunStateMachine.cs`

- 포탈을 통한 다음 스테이지 빌드를 위해 `InRun -> Initializing` 전이를 허용했다.
- 기존 마지막 스테이지 클리어 흐름인 `InRun -> RunCleared`는 유지했다.

### BossClearPortalController

파일: `Assets/_Project/Scripts/Runtime/Stage/BossClearPortalController.cs`

- 새 컴포넌트를 추가했다.
- 보스방 `RoomCleared` 이벤트를 받아 포탈 Visual과 Trigger를 활성화한다.
- 시작 시 포탈을 숨길 수 있다.
- 포탈 근처 플레이어를 감지하고, 상호작용 입력 시 `RunManager.NotifyBossClearPortalEntered()`를 호출한다.
- `InputManager.InteractButton`을 우선 사용하고, 입력 연결이 없을 경우 `E` 키를 fallback으로 사용한다.
- 포탈 Trigger 위치가 어긋나는 문제에 대비해 `activationRadius` 기반 거리 검사도 포함했다.

### BossClear 테스트 씬

파일: `Assets/Scenes/Test/BossClear.unity`

- `BossClearPortal`과 자식 `Square` 위치가 서로 크게 어긋나 있던 문제를 수정했다.
- 자식 `Square`의 `localPosition`을 `(0, 0, 0)`으로 맞췄다.
- 부모 `BossClearPortal`을 실제 포탈이 보이는 위치로 이동해 Visual과 Collider 판정 위치를 일치시켰다.

## 현재 설정 기준

`BossClearPortalController` 설정:

- `Room Controller`: 보스방 `RoomEntryRuntimeController`
- `Portal Visual Root`: 자식 `Square`
- `Portal Trigger`: `BossClearPortal`의 `BoxCollider2D`
- `Hide On Start`: true
- `Hide After Use`: true
- `Activation Radius`: 기본 1.5
- `Fallback Interact Key`: E

`RunManager` 설정:

- `totalStageCount = 1`이면 포탈 상호작용 후 결과창으로 진입한다.
- `totalStageCount > 1`이면 마지막 스테이지 전까지는 포탈 상호작용 후 다음 스테이지를 빌드한다.

## 예상 로그

정상 동작 시 콘솔에서 다음 흐름을 확인할 수 있다.

```text
[RunManager] Boss room cleared. Boss clear portal is ready. Stage=1/1.
[BossClearPortalController] Portal used by '...'
[RunManager] InRun -> RunCleared
[RunManager] RunCleared -> Resulting
[RunManager] Resulting state — RunResultPanelView shown.
```

## 테스트 여부

- `git diff --check` 통과
  - 대상: `RunManager.cs`, `RunStateMachine.cs`, `BossClearPortalController.cs`, `BossClear.unity`

- `dotnet build Assembly-CSharp.csproj --no-restore` 미완료
  - 로컬 환경에 .NET SDK가 없어 실행할 수 없었다.

- Unity Play Mode 최종 확인 필요
  - 보스 처치 시 포탈 활성화 여부
  - 포탈 근처에서 상호작용 입력 시 결과창 진입 여부
  - `totalStageCount > 1`일 때 다음 스테이지 빌드 여부

## 남은 확인 사항

- 결과창 UI 프리팹 또는 씬 인스턴스가 실제 화면에서 정상적으로 보이는지 확인해야 한다.
- `RunResultData`의 `KillCount`, `TotalDamage`, `MemoryFragments`는 아직 실제 집계 소스가 연결되지 않은 값이므로 기본값 중심으로 표시된다.
- 다음 스테이지 빌드 시 기존 방/보상 구독이 정상 해제되고 새 방 컨트롤러가 다시 구독되는지 Play Mode에서 확인해야 한다.
- 포탈 상호작용 UX는 현재 최소 구현이다. 프롬프트 표시, 사운드, 이펙트, 입력 안내는 후속 작업으로 남아 있다.
