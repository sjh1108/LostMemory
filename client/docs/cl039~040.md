# CL-039 / CL-040 구현 현황 정리

기준일: 2026-04-24

## 문서 목적

`CL-039 Charge Enemy 1차 구현`과 `CL-040 Charge Enemy 품질 보강/확장`의 오늘 작업 기준 실제 반영 상태를 정리한다.  
계획 문서는 `docs/cl039_cl040_charge_enemy_plan.md`를 기준으로 하고, 이 문서는 현재 프로젝트에 반영된 결과와 남은 작업을 기록한다.

## 범위 및 현재 판단

| Jira ID | 범위 | 현재 상태 |
|---|---|---|
| CL-039 | Orc Rider 돌진 적 1차 구현 | 플레이 가능한 수준까지 반영 |
| CL-040 | 돌진 전조/판정/재사용 구조 보강 | 일부 선반영, 최종 마감 전 추가 작업 필요 |

## 오늘 반영된 핵심 내용

### 1. Orc Rider 프리팹 구성

- `Orc_CL037.prefab` 기반으로 `OrcRider_CL039.prefab` 분기
- 무기 기반 근접 공격 대신 `CharacterDamageDash2D` 기반 돌진 공격 구조 적용
- `ChargeDamageArea`는 평소 비활성, dash 중에만 활성되도록 연결
- `CharacterHandleWeapon`, `WeaponAttachment` 계열은 향후 직접 공격 패턴 확장 여지를 남긴 상태
- 사방향 판정 정리를 위해 `ChargeHitboxAnchor`를 추가하고, `ChargeDamageArea`를 그 자식으로 이동
- 현재 구조에서 높이 보정은 `ChargeHitboxAnchor`, 회전은 `ChargeDamageArea`, 실제 판정은 `ChargeDamageArea > BoxCollider2D`가 담당

### 2. 애니메이션 / Animator

- Rider용 `Idle`, `Walk`, `Hurt`, `Death`, `Attack03_Charge` 클립 연결 완료
- 전조 중에는 `Block` 모션, 실제 돌진 시작 시에는 `OrcRider_Attack03_Charge` 모션 재생 구조로 정리
- `Any State -> Charge` self-transition 문제를 제거해서 대시 공격 1프레임 반복 현상 수정
- `Charge -> Idle/Walk`는 `Dashing == false` 기준으로 복귀하도록 정리
- `Telegraph` 중 사망 시 `Death` 전이를 덮어쓰지 않도록 전조 복귀 로직 보강

### 3. AI 상태 흐름

- `AIBrain` 상태를 `Detecting -> Moving -> Telegraph -> Charge -> Recover`로 정리
- `Moving -> Telegraph`는 거리 조건과 dash 쿨다운 준비 완료 조건을 동시에 만족할 때만 진입
- `Telegraph` 진입 시 dash 방향을 잠그고, 이후에는 재조준 없이 그 방향으로 그대로 돌진
- `Telegraph`가 시작된 뒤에는 타깃이 공격 범위나 추적 범위를 벗어나도 해당 공격은 취소하지 않음
- `Telegraph`는 시간 종료 후 무조건 `Charge`, `Charge`는 시간 종료 후 `Recover`, `Recover`는 시간 종료 후 다시 `Moving`

### 4. 공통 전조 시스템 선반영

- `AttackTelegraph2DView`를 추가해서 박스형 공격 예고를 공통 컴포넌트로 분리
- `AIBrainDashTelegraphDriver`를 추가해서 Orc Rider의 AI 상태와 전조 뷰를 연결
- 전조 박스는 `ChargeDamageArea`의 콜라이더 크기와 `DashDistance`를 기준으로 계산
- 실제 dash 방향과 전조 박스 방향이 다르지 않도록, 전조 진입 시 잠근 방향을 `CharacterDash2D`와 `ChargeDamageArea` 회전에 같이 반영
- 이 구조는 이후 보스나 다른 돌진 적에게 재사용 가능한 기반으로 유지

### 5. 엔진/전투 보정

- `CharacterDash2D` dash 종료 시 `_dashDestination`으로 한 번 더 맞춘 뒤 종료하도록 보정해서 전조 길이와 실제 이동 끝점 차이를 줄임
- `DamageOnTouch`는 `OnTriggerEnter2D` / `OnTriggerStay2D` 둘 다 처리하는 구조를 그대로 사용
- `Dash`와 `Block`에는 현재 무적/슈퍼아머를 부여하지 않음

## 현재 핵심 설정값

### `OrcRider_CL039.prefab`

- `DashDistance = 4.5`
- `DashDuration = 0.32`
- `TelegraphDuration = 0.5`
- `ChargeDuration = 0.32`
- `RecoverDuration = 0.45`
- dash cooldown 소비 시간: `1.2`
- `InvincibleWhileDashing = 0`

### `AIBrainDashTelegraphDriver`

- `rotateChargeDamageAreaWithDash = 1`
- `telegraphLengthPadding = 0`
- `telegraphWidthPadding = 0.1`
- `playTelegraphAnimation = 1`
- `telegraphAnimationStateName = OrcRider_Blcok`
- `telegraphStateName = Telegraph`
- `chargeStateName = Charge`

### 히트박스 구조

- `ChargeHitboxAnchor.localPosition.y = 0.19`
- `ChargeDamageArea BoxCollider2D.offset = (0, 0)`
- `ChargeDamageArea BoxCollider2D.size = (2.2, 3)`

현재 구조에서 조정 기준은 아래처럼 분리한다.

- 몸 높이 조정: `ChargeHitboxAnchor.localPosition.y`
- 전방으로 더 내밀기: `ChargeDamageArea BoxCollider2D.offset.x`
- 실제 판정 크기 조정: `ChargeDamageArea BoxCollider2D.size`
- `offset.y`는 사방향 회전 구조를 깨기 쉬우므로 기본적으로 `0` 유지

## CL-039 기준 완료 판단

현재 기준으로 아래 항목은 1차 완료로 본다.

- Rider 전용 애니메이션 클립 생성 및 연결
- 전조 -> 돌진 -> 회복 루프 동작
- 전조 중 방향 잠금 및 재조준 금지
- dash 중에만 활성화되는 돌진 타격 판정 연결
- 전조 박스 시각화 추가
- 전조 중 사망 시 death 전이 보정
- 대시 공격 애니메이션 반복/누락 주요 원인 수정

## CL-040 관점에서 이미 선반영된 부분

- 재사용 가능한 `AttackTelegraph2DView`
- Rider 전용 연결 드라이버 `AIBrainDashTelegraphDriver`
- 거리 + dash 준비 완료를 함께 보는 `AIDecisionDistanceToTargetAndDashReady`
- 사방향 회전 히트박스를 위한 `ChargeHitboxAnchor + ChargeDamageArea` 분리 구조

즉 CL-040 전체가 끝난 것은 아니지만, 전조 재사용 구조와 판정 구조 일부는 이미 들어간 상태다.

## 아직 남은 작업 / 추가 조정 필요

- 사방향 대시 피격 범위 최종 미세조정
- 전조 박스와 실제 타격 박스 체감 일치도 추가 확인
- `Block`의 게임플레이 의미 정의
  - 무적
  - 슈퍼아머
  - 넉백 무시
  - 피해 감소
- Rider의 직접 공격 패턴 추가 여부 및 연결
- 대시/전조 관련 VFX, SFX, 히트 피드백 추가
- 보스/다른 적 재사용 검증

## 주의 메모

- 현재 전조 애니메이션 상태 이름은 기존 자산 이름 기준으로 `OrcRider_Blcok` 오타를 그대로 사용 중이다.  
  상태/클립 이름을 정리할 경우 드라이버 참조 문자열도 같이 바꿔야 한다.
- 사방향 판정 보정은 `offset.y` 하나로 해결하려고 하면 방향별로 다시 어긋난다.  
  높이 보정은 앵커, 전방 보정은 `offset.x`로 분리해서 다루는 것이 현재 구조의 기준이다.
