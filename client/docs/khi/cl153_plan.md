### 5. 분포 audit 도구

CL-152 의 `Audit RewardPool Distribution` 메뉴 + 신규 `Audit BuildSet Counts` 메뉴:

```csharp
[MenuItem("Tools/LostMemory/Audit BuildSet Tag Distribution")]
public static void AuditTagDistribution()
{
    var pool = AssetDatabase.LoadAssetAtPath<RewardPool>("...");
    var counts = new Dictionary<RelicTag, int>();
    foreach (var r in pool._allRewards)
    {
        if (r.TagPrimary != RelicTag.None) counts[r.TagPrimary] = counts.GetValueOrDefault(r.TagPrimary) + 1;
        if (r.TagSecondary != RelicTag.None) counts[r.TagSecondary] = counts.GetValueOrDefault(r.TagSecondary) + 1;
    }
    foreach (var (k, v) in counts.OrderByDescending(kv => kv.Value))
        Debug.Log($"  {k}: {v}");
}
```

→ items_draft V0.4 의 1.8× 도달 표와 비교.

## 위험 / 결정 미정

### 위험

1. **시간 초과**: 5런 플레이테스트가 가장 비싼 비중. 1런이 1시간 가정이지만 실제 보스까지 30~60분 + 기록 + 재시작 → 총 6시간 가능. → 단위 회귀 + 5런 = **9~10시간** 가능. 3점 표보다 큼. **분할**: A+C+D 단위 (3시간) 와 B 플레이테스트 (5~6시간) 를 별 PR/별 세션.
2. **버그 발견 시 fix vs 기록**: 즉시 fix 가 본 CL 범위인지 모호. → 카테고리 A (사소한 fix) 만 즉시, 나머지는 별 ticket 또는 CL-154.
3. **멀티 검증 환경 부담**: 호스트+클라이언트 두 인스턴스 띄워야. 호스트 본인 + 동료 1명 협업 또는 같은 PC 두 빌드. → MVP 는 sanity 1런으로만.
4. **밸런스 판정 주관성**: "OP" / "약체" 정의 모호. → 본 CL 은 의심 식별까지, 정량적 검증은 별도 ticket.
5. **CL-149 (툴팁) 미완성 시 영향**: 다른 사람이 진행 중이라 본 CL 시작 시점 미완 가능. 툴팁 hover 검증은 skip 가능.
6. **Audit 메뉴가 75개 등록 가정**: CL-152 의 풀 등록 메뉴가 먼저 실행되어야. 의존 명시.
