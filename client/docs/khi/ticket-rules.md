# 티켓 작성 규칙

이 문서는 `CL-XXX` 형식 티켓의 작성·관리 규칙을 정의합니다. 티켓 마스터는 [tickets-master.md](tickets-master.md) 참조.

## 1. 티켓 ID

- 형식: `CL-XXX` (3자리 숫자, 0 패딩 없음 — `CL-9`, `CL-99`, `CL-100`)
- 클라이언트 작업은 `CL-` 접두사 사용
- 신규 Epic의 임시 prefix(예: `S-01`)는 마스터 등록 시 다음 가용 `CL-XXX`로 변환

## 2. 필드 정의

| 필드 | 설명 | 예시 |
|---|---|---|
| MVP 차수 | 1차 / 2차 / 3차 / 미정 | `1차 MVP` |
| Epic | Epic 코드 + 이름 | `Epic B. 플레이어 전투 / 조작` |
| 카테고리 | 작업 영역 분류 | `Combat/Core`, `UI/Run`, `Session/Network` |
| 작업코드 | 티켓 ID | `CL-009` |
| 작업명 | 한 줄 요약 (~30자) | `검 1~3타 기본 공격 구현` |
| 담당자 | `클라1` / `클라2` / `클라3` | `클라1` |
| 우선순위 | `P0` / `P1` / `P2` | `P0` |
| 산출물 | 검증 가능한 결과물 | `기본 공격 콤보` |
| 예상 점수 | 1 / 2 / 3 / 5 (8 이상은 쪼갤 것) | `5` |
| 설명 | 한두 문장 작업 내용 | `검 1타, 2타, 3타와 기본 타격 판정 흐름을 구현한다.` |
| 의존성 | 선행 티켓 ID들 (`;`로 구분) | `CL-008` 또는 `CL-008;CL-013` |

## 3. 점수 가이드

작업 시간 추정. 티켓이 5점을 넘으면 무조건 쪼갠다.

| 점수 | 의미 | 작업 시간 | 예시 |
|---|---|---|---|
| **1** | 문서/체크리스트/설정값 변경 | 1~2시간 | QA 항목 정리, 시드 고정값 검증 |
| **2** | 단순 구현 1개 | 반나절 | 단일 컴포넌트 추가, 단순 wiring |
| **3** | 일반 기능 1개 | 1일 | 상태머신, UI 화면 1종, 데이터 구조 + 모델 |
| **5** | 복합 기능 (필요할 때만) | 1~2일 | 콤보 시스템, 4종 인챈트 통합 구현 |
| **8+** | 너무 큼 → **쪼개기** | - | "hook 4곳 + 유물 6종" 같은 묶음 |

**그래뉼래리티 원칙**: "종류별 1티켓"이 아니라 **"레이어별 1티켓"**.
- ❌ 잘못된 예: 빌드 14종을 14개 티켓으로
- ✅ 올바른 예: `데이터 구조 → 매니저 → 효과 적용 → 단순 빌드 8종 묶음 → 인챈트 4종 묶음 → UI → QA`

기존 Epic J(재능 시스템) 9개 티켓이 모범 사례.

## 4. 우선순위

| 등급 | 의미 | 적용 |
|---|---|---|
| **P0** | 데모/MVP 핵심 경로 | 빠지면 그 차수 데모 불가능 |
| **P1** | 중요하지만 우회 가능 | 빠져도 데모는 굴러감 (품질 손실) |
| **P2** | 후순위 / 폴리싱 / 확장 | 시간 남으면 |

## 5. Epic 분류

| Epic | 영역 | 차수 |
|---|---|---|
| A | 프로젝트 기반 / 기술 세팅 | 1차 |
| B | 플레이어 전투 / 조작 | 1차 |
| C | 멀티플레이 / 세션 네트워크 | 1차 |
| D | 전투 공간 흐름 / 방 인터랙션 | 1차 |
| E | 일반 적 전투 구현 / 버그 수정 | 1차 |
| F | 보상 / 상점 / 성장 선택 | 1차 |
| G | 보스전 / 런 종료 | 1차 |
| H | UI / 연출 / 아트 적용 | 1차 |
| I | 통합 / QA / 데모 안정화 | 1차 |
| J | 메타 성장 / 기억·재능 | 2~3차 |
| K | 콘텐츠 / 무기 확장 | 2~3차 |
| L | 백엔드 연동 / 저장 | 3차 |
| M | 스토리 / 진행 상태 | 3차 |
| N | 확장 콘텐츠 / 이벤트·보스 확장 | 3차 |
| O | 제작 파이프라인 / 에셋 규칙 | 3차 |
| P | 유물 세팅 및 / 연동 | 1~2차 |
| Q | 1차 MVP 통합 데모 흐름 | 1차 |
| R | 마을 / 귀환 흐름 | 1차 |
| **S** | **빌드 시스템 (유물 빌드 트리)** | **2차** |
| **U** | **밸런스 에디터 (개발 툴)** | **1~2차 병렬** |
| **V** | **스토리 / 컷씬 / 내러티브** | **3차** |

> Epic T(미소녀)는 별도 Epic으로 분리하지 않고 Epic S 안에 흡수 (미소녀가 빌드의 한 카테고리이고, floating 형태라 동료 AI 불필요).

## 7. 의존성 표기

- 형식: `CL-008` (단일) 또는 `CL-008;CL-013` (다중)
- 의존성은 **선행 완료 필요**한 티켓만 명시
- 같은 Epic 내 인접 작업은 자연스러운 순서면 굳이 안 적어도 됨
- 외부 시스템 의존(노션 등)은 설명에 명시

## 8. 신규 티켓 작성 절차

1. `tickets-master.md`에서 다음 가용 `CL-XXX` 확인
2. 이 문서 §2 필드 다 채워서 추가
3. Epic이 §5에 없으면 §5 먼저 갱신
4. 점수 5 초과면 쪼개고 시작
5. 의존성 그래프에 사이클 없는지 확인

## 9. 작업 진행 시 규칙

- 티켓 작업 시작 전 `docs/khi/cl{번호}_*.md` 형태로 상세 plan 문서 작성 (기존 패턴 유지)
- plan 문서에는 구현 방식·파일 경로·검증 방법 포함
- 작업 완료 시 마스터에서 상태 업데이트
- 의존 티켓이 미완료면 시작 안 함 (또는 의존 재정의)

## 10. AGENTS / Claude 작업 시

- 신규 티켓 추가 요청 시 이 문서 §2~§7 따른 형식으로 작성
- 작업명 · Epic · 카테고리 · 점수 · 의존성 누락하지 말 것
- 큰 작업 요청 받으면 §3 따라 5점 단위로 쪼개서 제안
