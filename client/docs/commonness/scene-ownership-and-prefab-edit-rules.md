# Scene Ownership And Prefab Edit Rules

> 대상 프로젝트: `client/LostMemory`  
> 목적: Unity 씬과 공용 프리팹 수정 충돌을 줄이고, 원본 자산을 보호한다.

## 1. 기본 원칙

- 씬은 가능한 한 여러 사람이 동시에 수정하지 않는다.
- 실제 게임 씬은 담당자 또는 소유자가 직접 관리한다.
- 다른 사람이 관리하는 씬을 수정해야 하면 원본을 바로 고치지 말고 복제본에서 작업한다.
- 공용 프리팹 수정은 가급적 피한다.
- 공용 프리팹을 수정해야 하면 담당자 승인 또는 리뷰를 먼저 받는다.
- 외부 에셋 원본은 직접 수정하지 않는다.

## 2. 씬 수정 규칙

### 2.1 실제 게임 씬

실제 게임 진행에 사용되는 씬은 충돌 위험이 크므로 소유자를 둔다.

예시:

```text
Assets/_Project/Scenes/Lobby/Lobby.unity
Assets/_Project/Scenes/Stages/Stage01.unity
```

규칙:

- 소유자만 직접 수정한다.
- 비소유자가 수정해야 하면 작업 전에 소유자에게 공유한다.
- 구조 변경, 매니저 추가, 주요 오브젝트 삭제는 리뷰 후 반영한다.
- 급한 실험은 실제 게임 씬에서 하지 않는다.

### 2.2 테스트 씬

기능 검증이나 개인 실험은 테스트 씬에서 한다.

권장 위치:

```text
Assets/_Project/Scenes/Test/
```

이름 규칙:

```text
Test_CombatRoom_KHI.unity
Test_PlayerDash_AD.unity
Test_RelicReward_UI.unity
```

규칙:

- 개인 테스트 씬은 해당 작업자가 자유롭게 수정할 수 있다.
- 다른 사람의 테스트 씬을 수정해야 하면 새로 복제해서 사용한다.
- 테스트가 끝난 임시 씬은 머지 전에 삭제하거나 유지 이유를 남긴다.

## 3. 씬 복제 규칙

기존 씬을 기반으로 작업해야 할 때는 원본을 직접 수정하지 않고 복제해서 사용한다.

예시:

```text
Stage01.unity
Stage01_KHI_Work.unity
Test_Stage01_Combat_AD.unity
```

복제 후 작업해야 하는 경우:

- 다른 사람이 소유한 씬에서 테스트가 필요할 때
- 큰 구조 변경을 실험할 때
- 배치, 조명, 매니저, 스폰 지점처럼 충돌 가능성이 큰 변경을 할 때
- 아직 합의되지 않은 기능을 붙여볼 때

원본 씬에 반영할 때:

- 변경 목적을 공유한다.
- 필요한 오브젝트나 프리팹만 원본으로 옮긴다.
- 씬 전체를 덮어쓰지 않는다.

## 4. 공용 프리팹 수정 규칙

공용 프리팹은 여러 씬과 기능에서 함께 쓰는 프리팹이다.

예시:

```text
Player_Sephiria.prefab
Enemy_Ninja.prefab
Weapon_Sword.prefab
UI_HUD.prefab
Manager_Run.prefab
Room_Combat_Small_01.prefab
Camera_Main.prefab
```

규칙:

- 공용 프리팹은 가급적 직접 수정하지 않는다.
- 수정이 필요하면 담당자 승인 또는 리뷰를 받는다.
- 수치 변경은 담당자에게 공유 후 진행할 수 있다.
- 컴포넌트 추가, 삭제, 계층 구조 변경은 리뷰 후 진행한다.
- 공용 프리팹 실험은 복제본에서 먼저 한다.

복제 예시:

```text
Player_Sephiria.prefab
Player_Sephiria_AD_Test.prefab
```

## 5. 프리팹 수정 권한 기준

| 변경 종류 | 권한 기준 |
|---|---|
| 개인 테스트 프리팹 수정 | 자유 수정 |
| 개인 기능 전용 프리팹 수정 | 담당자 자유 수정 |
| 공용 프리팹 수치 변경 | 담당자 승인 권장 |
| 공용 프리팹 컴포넌트 추가/삭제 | 리뷰 필요 |
| 공용 프리팹 계층 구조 변경 | 리뷰 필요 |
| 매니저/카메라/플레이어 핵심 프리팹 변경 | 담당자 승인 또는 리뷰 필수 |
| 외부 에셋 원본 프리팹 변경 | 금지 |

## 6. 외부 에셋 수정 금지

다음 폴더는 외부 에셋 원본으로 본다.

```text
Assets/TopDownEngine
Assets/CodeRespawn
Assets/MMData
```

규칙:

- 외부 에셋 원본 스크립트와 프리팹은 직접 수정하지 않는다.
- 필요한 경우 `_Project` 아래로 복제해서 수정한다.
- 외부 에셋과 연결하는 코드는 `Assets/_Project/Scripts/Runtime/Integrations` 아래에 둔다.
- 외부 에셋 데모 씬은 참고용으로만 사용한다.

## 7. 작업 전 체크리스트

씬이나 프리팹을 수정하기 전에 확인한다.

- 이 파일이 실제 게임 씬인가?
- 이 파일에 소유자나 담당자가 있는가?
- 다른 사람도 동시에 수정할 가능성이 있는가?
- 복제본에서 작업하는 편이 안전한가?
- 공용 프리팹이라면 담당자 승인 또는 리뷰가 필요한가?
- 외부 에셋 원본을 직접 수정하고 있지는 않은가?

## 8. 권장 운영 방식

- 실제 게임 씬은 작업 시작 전에 팀 채널에 공유한다.
- 공용 프리팹 변경은 PR 또는 코드 리뷰에서 확인한다.
- 실험은 `Scenes/Test`와 테스트용 프리팹에서 먼저 한다.
- 원본 씬과 공용 프리팹에는 검증된 변경만 반영한다.
- Unity 씬 충돌이 발생하면 자동 머지보다 담당자 확인을 우선한다.
