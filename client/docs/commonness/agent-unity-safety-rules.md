# Agent Unity Safety Rules

> 대상 프로젝트: `client/LostMemory`  
> 목적: CLI, Codex, AI 에이전트가 Unity 프로젝트 파일을 수정할 때 씬, 프리팹, 외부 에셋을 실수로 망가뜨리지 않게 한다.

## 1. 최우선 원칙

- `.unity`, `.prefab`, `.asset`, `.meta` 파일은 사용자가 명시적으로 요청하지 않으면 직접 수정하지 않는다.
- Unity 씬과 프리팹 작업은 가능하면 Unity Editor에서 수행할 단계로 설명한다.
- CLI로 Unity 직렬화 파일을 수정해야 할 때는 먼저 위험과 변경 범위를 사용자에게 확인한다.
- 외부 에셋 원본은 직접 수정하지 않는다.
- 공용 씬과 공용 프리팹은 복제본 또는 테스트 파일에서 먼저 작업한다.

## 2. 기본 금지 파일

다음 확장자는 자동 편집을 피한다.

```text
.unity
.prefab
.asset
.meta
.controller
.anim
.overrideController
.mat
.renderTexture
.playable
```

예외:

- 사용자가 해당 파일 수정을 명시적으로 요청한 경우
- 단순 문서화가 아니라 실제 Unity 에셋 변경이 목표인 경우
- 변경 전후 위험을 설명했고 사용자가 진행을 승인한 경우

## 3. 외부 에셋 보호 규칙

다음 경로는 외부 에셋 원본으로 본다.

```text
LostMemory/Assets/TopDownEngine/
LostMemory/Assets/CodeRespawn/
LostMemory/Assets/MMData/
```

규칙:

- 위 경로의 파일은 직접 수정하지 않는다.
- 필요한 기능은 `LostMemory/Assets/_Project/` 아래에 새 파일을 만들어 연결한다.
- 외부 에셋 데모 씬이나 데모 프리팹은 참고용으로만 본다.
- 외부 에셋을 바꿔야 할 것 같으면 먼저 대체 방법을 제안한다.

## 4. 안전하게 수정 가능한 기본 대상

명시적 요청이 있거나 작업 목적에 맞으면 다음 파일은 비교적 안전하게 수정할 수 있다.

```text
docs/**/*.md
LostMemory/Assets/_Project/Scripts/**/*.cs
LostMemory/Assets/_Project/Scripts/**/*.asmdef
LostMemory/Assets/_Project/**/*.md
```

단, `_Project` 아래라도 `.unity`, `.prefab`, `.asset`, `.meta`는 1번 원칙을 따른다.

## 5. 씬 작업 시 행동 규칙

씬 관련 요청을 받으면 먼저 다음을 확인한다.

- 실제 게임 씬인가?
- 테스트 씬인가?
- 기존 씬을 수정해야 하는가?
- 복제본에서 작업해도 되는가?
- Unity Editor에서 직접 해야 하는 작업인가?

기본 대응:

- 실제 게임 씬은 직접 수정하지 않고 작업 절차를 설명한다.
- 실험이 필요하면 `Assets/_Project/Scenes/Test/` 아래 테스트 씬 생성을 제안한다.
- 기존 씬 기반 작업은 원본 수정 대신 복제본 사용을 제안한다.
- YAML 직접 편집은 마지막 수단으로만 사용한다.

권장 복제 이름:

```text
Stage01_KHI_Work.unity
Test_Stage01_Combat_AD.unity
Test_PlayerDash_AD.unity
```

## 6. 프리팹 작업 시 행동 규칙

프리팹 관련 요청을 받으면 먼저 다음을 확인한다.

- 공용 프리팹인가?
- 개인 테스트 프리팹인가?
- 외부 에셋 원본 프리팹인가?
- 컴포넌트나 계층 구조를 바꾸는 작업인가?

기본 대응:

- 공용 프리팹은 직접 수정하지 않는다.
- 공용 프리팹 변경이 필요하면 담당자 승인 또는 리뷰가 필요하다고 안내한다.
- 실험은 복제 프리팹에서 하도록 제안한다.
- 외부 에셋 원본 프리팹은 수정하지 않고 `_Project/Prefabs` 아래 복제본 사용을 제안한다.

권장 복제 이름:

```text
Player_Sephiria_AD_Test.prefab
Enemy_Ninja_KHI_Work.prefab
UI_HUD_AD_Test.prefab
```

## 7. 작업 전 체크리스트

Unity 파일을 수정하기 전 반드시 확인한다.

- 변경 대상이 `.unity`, `.prefab`, `.asset`, `.meta`인가?
- 외부 에셋 경로 아래 파일인가?
- 공용 씬 또는 공용 프리팹인가?
- 사용자가 직접 수정을 명시했는가?
- 문서나 C# 코드 수정으로 해결할 수 있는가?
- 복제본에서 작업하는 편이 안전한가?

하나라도 위험하면 바로 수정하지 말고 사용자에게 확인하거나 작업 절차를 제안한다.

## 8. 사용자 확인이 필요한 경우

다음 경우에는 수정 전에 사용자 확인을 받는다.

- 실제 게임 씬 수정
- 공용 프리팹 수정
- 외부 에셋 원본 수정
- `.meta` 파일 수정
- 여러 Unity 직렬화 파일을 한 번에 수정
- Unity가 자동 생성하거나 관리하는 설정 파일 수정
- 파일 이동 또는 이름 변경으로 GUID 참조가 바뀔 수 있는 작업

확인 문장 예시:

```text
이 작업은 공용 프리팹을 직접 수정합니다. 복제본에서 먼저 작업할까요, 아니면 원본 수정을 진행할까요?
```

```text
이 씬은 실제 게임 씬으로 보입니다. 원본 대신 테스트 씬으로 복제해서 작업하는 방식으로 진행할까요?
```

## 9. 권장 응답 방식

Unity 씬이나 프리팹 요청에 바로 파일 수정을 시작하지 않는다.

먼저 다음 중 하나로 응답한다.

- Unity Editor에서 수행할 단계 안내
- 테스트 씬 또는 복제 프리팹 생성 제안
- 변경 대상의 위험 설명
- 사용자의 승인 요청
- C# 스크립트나 문서 수정으로 대체하는 방안 제안

## 10. 예외 처리

사용자가 명확히 다음처럼 요청하면 수정할 수 있다.

```text
이 prefab 파일 직접 수정해줘
이 unity 씬 YAML 수정해도 돼
외부 에셋 원본 수정해도 돼
meta 파일까지 같이 바꿔줘
```

그래도 다음 순서를 지킨다.

1. 변경 대상과 위험을 짧게 설명한다.
2. 가능한 경우 복제본 또는 백업 방식을 제안한다.
3. 승인 후 최소 범위만 수정한다.
4. 변경 후 어떤 Unity 파일을 건드렸는지 명확히 보고한다.
