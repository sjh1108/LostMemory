# CL-049 / CL-050 구현 현황

## 문서 목적

`CL-049 보스방 진입 조건 계산 구현`과 `CL-050 보스방 문 분기·입장 흐름 구현`의 현재 구현 상태를 정리한다.

이 문서는 기존 계획 문서인 `docs/cl049_boss_room_entry_condition_plan.md`, `docs/cl050_boss_room_door_and_entry_flow_plan.md`를 기준으로, 실제로 어떤 런타임/에디터/테스트 씬 구성이 반영되었는지와 현재 완료 범위를 남기는 용도다.

## 대상 스토리

| Jira ID | 범위 | 담당 |
|---|---|---|
| CL-049 | 보스방 진입 조건 계산 구현 | 클라2 |
| CL-050 | 보스방 문 분기·입장 흐름 구현 | 클라2 |

## 구현 방향

- 구현은 `_Project/Scripts/Runtime/Stage` 아래의 프로젝트 소유 C# 런타임으로 분리했다.
- `CL-049`는 순수 계산 로직과 상태 보관 로직을 먼저 정리하고, `CL-050`은 그 결과를 구독해 문 상태와 입장 흐름을 제어하도록 분리했다.
- 현재 보스방 진입은 `기존 공용 출구 재사용`이 아니라 `보스 전용 문/포탈` 방향으로 구성했다.
- 실제 이동은 우선 `같은 씬 내부 로컬 텔레포트` 방식으로 구현했다.
- 검증은 전용 수동 테스트 씬 `BossEntryTest`, `BossDoorTest`를 기준으로 진행했다.

## 구현 결과

### CL-049 보스방 진입 조건 계산

- `StageRoomType`, `BossEntryRequirementMode`, `StageRoomProgress`를 추가해 방 타입, 보스 선행 조건 포함 여부, 방문/완료 상태를 모델링했다.
- `BossRoomEntryConditionCalculator`를 추가해 `첫 번째 보스방 이전 구간`만 평가하도록 구현했다.
- 기본 규칙은 `Combat 방은 필수`, `Shop/Event 방은 기본 제외`로 두고, `Required` / `Ignored` override를 지원한다.
- 보스방 진입 판단은 `Visited`가 아니라 `Completed` 기준으로 계산한다.
- 계산 결과는 단순 bool이 아니라 아래 정보를 함께 반환한다.
  - `HasBossRoom`
  - `HasConfiguredRequirements`
  - `RequiredRoomCount`
  - `CompletedRequiredRoomCount`
  - `RemainingRequiredRoomCount`
  - `FirstIncompleteRoomSequenceIndex`
  - `FirstIncompleteRoomId`
  - `CanEnterBossRoom`
- `BossRoomEntryTracker`를 추가해 방 시퀀스 설정, 방문/완료 처리, 조건 재계산, 상태 변경 이벤트 발행을 담당하도록 구성했다.
- `BossRoomEntryTrackerEditor`를 추가해 Unity Inspector에서 보스방 진입 조건을 수동 검증할 수 있도록 했다.

### CL-050 보스방 문 상태 및 입장 흐름

- `BossRoomDoorController`를 추가해 보스 문 상태를 아래 상태 머신으로 관리하도록 구현했다.
  - `Locked`
  - `UnlockedIdle`
  - `WaitingForParty`
  - `EntryConfirmed`
  - `Transitioning`
- `BossRoomEntryInteractionZone`를 추가해 트리거 존 안의 플레이어만 상호작용 입력을 보내도록 구성했다.
- 솔로 기준으로는 조건 충족 후 상호작용 시 즉시 입장 흐름이 시작되도록 했다.
- 코옵 확장용으로 참여자 ready 집계 구조를 넣었고, 문 컨트롤러가 참여자 상태를 수집하도록 구성했다.
- `BossRoomDoorView`를 추가해 문 잠금/해제에 따라 blocking collider를 켜고 끄고, 상태 색상을 문 렌더러 또는 outline에 반영하도록 했다.
- `LineRenderer` 기반 outline 표시를 지원하도록 확장해, 테스트 씬에서는 인식 범위 테두리 색으로 잠금/해제 상태를 확인할 수 있게 했다.
- `BossRoomEntryTransitionRequest`를 추가해 문 판정과 실제 이동 처리를 이벤트 기반으로 분리했다.

### CL-050 같은 씬 보스 구역 이동

- `BossRoomEntryPoint`를 추가해 보스 구역 도착 지점과 도착 방향을 정의할 수 있게 했다.
- `BossRoomLocalTransitionDriver`를 추가해 `BossRoomDoorController.BossRoomEntryStarted` 이벤트를 받아 같은 씬 내부 도착 지점으로 플레이어를 이동시키도록 구현했다.
- 도착 포인트의 자식 Transform을 `Arrival Point`로 사용해 코옵 플레이어 슬롯 배치를 지원하도록 했다.
- 이동 시 필요한 경우 플레이어를 잠깐 `Freeze / UnFreeze`하고, 도착 방향으로 회전시키는 옵션을 제공한다.

## 테스트 씬 구성

### BossEntryTest

- `BossRoomEntryTracker` 중심 수동 검증 씬으로 사용했다.
- 방 시퀀스와 완료 상태를 Inspector에서 조작해 보스방 진입 가능 여부를 확인할 수 있도록 구성했다.

### BossDoorTest

- `BossRoomDoorController`, `BossRoomEntryInteractionZone`, `BossRoomDoorView`, `BossRoomLocalTransitionDriver`를 함께 검증하는 씬으로 사용했다.
- 문 잠금/해제, 상호작용, 보스 구역 이동 흐름을 수동으로 확인할 수 있도록 구성했다.
- 보스 구역과 도착 포인트는 현재 임시 검증용 구조이며, 최종 스테이지 씬 구성은 아니다.

## 현재 검증 결과

2026-04-26 기준 Unity 수동 테스트에서 아래 항목을 확인했다.

- `BossRoomEntryTracker`의 조건 계산 결과가 Inspector에서 정상적으로 갱신된다.
- 필수 전투방 완료 여부에 따라 보스 문 잠금/해제 상태가 전환된다.
- 문 앞 상호작용 존에서 `E` 입력 시 보스방 진입 시작 로그가 출력된다.
- 같은 씬 내부의 `BossRoomEntryPoint`로 플레이어를 이동시키는 로컬 텔레포트 흐름이 동작한다.
- 문 상태에 따라 blocker collider on/off와 outline 색상 반영을 수동 확인할 수 있다.
