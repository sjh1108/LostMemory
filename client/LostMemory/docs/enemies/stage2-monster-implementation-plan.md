# 2스테이지 몬스터 구현 계획서

## 목적

2스테이지 전용 기본 몬스터 3종과 엘리트 몬스터 2종을 구현한다. 각 몬스터는 기존 던전 스폰 구조인 `EnemyCatalog`와 `RoomData`를 통해 배치 가능해야 하며, 체력, 이동속도, 공격력 같은 주요 수치는 `EnemyData` 기준으로 관리한다.

## 구현 대상

### 기본 몬스터

- 박쥐
  - 간단한 근접 공격
  - 비행 몬스터
  - 벽을 제외한 장애물 무시
  - 사용 에셋: `ERW - Cemetery`

- 스켈레톤1
  - 기본 근접형 몬스터
  - 약공격 1종
  - 사용 에셋: `ERW - Crypt`

- 어쌔신
  - 플레이어 뒤로 텔레포트
  - 텔레포트 후 공격

### 엘리트 몬스터

- 엘리트 스켈레톤
  - 약공격 1종
  - 중공격 1종
  - 사용 에셋: `ERW - Old Prison`

- 스켈레톤 메이지
  - 원거리 마법 공격
  - 사용 에셋: `ERW - Old Prison`

## 공통 구현 원칙

- 외부 에셋 원본은 직접 수정하지 않는다.
- 실제 게임용 프리팹은 `Assets/_Project/Prefabs/Enemies` 아래에 생성한다.
- 몬스터별 밸런스 데이터는 `Assets/_Project/ScriptableObjects/Enemies` 아래 `EnemyData`로 분리한다.
- 스폰 연동은 `EnemyCatalog_Default`에 enemyId, prefab, data를 등록하는 방식으로 진행한다.
- 2스테이지 RoomData는 prefab을 직접 참조하지 않고 enemyId만 참조한다.
- 피격, 사망, 미니맵 표시, 방 클리어 카운트는 기존 몬스터와 동일한 흐름을 따른다.
- 커스텀 컨트롤러를 사용하는 몬스터도 `EnemyDataRuntimeAdapter`를 통해 런타임 밸런스 데이터가 반영되도록 한다.

## 권장 enemyId

```text
enemy_bat
enemy_skeleton_crypt
enemy_assassin
enemy_skeleton_elite
enemy_skeleton_mage
```

## 공통 프리팹 구성

각 몬스터 프리팹은 기본적으로 아래 구성을 가진다.

- `Rigidbody2D`
- `Collider2D`
- `Health`
- `MMHealthBar`
- `MinimapAgent`
- 몬스터별 전용 Controller 또는 TopDownEngine AI 구성
- `EnemyDataRuntimeAdapter` 적용 가능 구조
- 공격 판정 컴포넌트
- 피격/사망 애니메이션 연결

## 몬스터별 구현 계획

## 1. 박쥐

### 컨셉

박쥐는 2스테이지의 기본 비행 몬스터다. 플레이어를 발견하면 장애물의 영향을 적게 받으며 접근하고, 근접 거리에서 짧은 공격을 수행한다.

### 동작 흐름

```text
Idle
 -> Detect Player
 -> FlyApproach
 -> In Attack Range?
      yes -> PreAttack -> Attack -> Recover -> Cooldown
      no  -> FlyApproach 유지
```

### 구현 포인트

- 벽 레이어는 이동 제한 대상으로 유지한다.
- 일반 장애물은 무시할 수 있도록 충돌 레이어 또는 이동 판정을 분리한다.
- 공격은 짧은 전방 히트박스 또는 `DamageOnTouch` 기반으로 구현한다.
- 기존 지상 몬스터 AI로 처리하기 어렵다면 박쥐 전용 컨트롤러를 둔다.
- 비행 몬스터이므로 그림자, 높이감, 미니맵 표시가 어색하지 않게 확인한다.

### 완료 조건

- 박쥐가 2스테이지 방에서 정상 스폰된다.
- 벽은 통과하지 않고, 일반 장애물에는 막히지 않는다.
- 플레이어를 감지한 뒤 접근하여 공격한다.
- 사망 시 방 클리어 조건에 정상 반영된다.

## 2. 스켈레톤1

### 컨셉

스켈레톤1은 2스테이지의 기본 근접 몬스터다. 복잡한 패턴보다 읽기 쉬운 약공격 1종을 통해 2스테이지 초반 전투의 기준 몬스터로 사용한다.

### 동작 흐름

```text
Idle
 -> Detect Player
 -> Approach
 -> In Attack Range?
      yes -> LightAttack1 -> Recover -> Cooldown
      no  -> Approach 유지
```

### 구현 포인트

- 기존 오크 또는 근접형 몬스터 AI 구조 재사용 가능 여부를 먼저 확인한다.
- 약공격은 짧은 전방 히트박스 방식으로 구현한다.
- 공격 전 짧은 선딜을 두어 플레이어가 반응할 수 있게 한다.
- `EnemyData`로 HP, 이동속도, 공격력을 관리한다.

### 완료 조건

- 스켈레톤1이 정상 스폰된다.
- 플레이어를 감지하고 접근한다.
- 사거리 진입 시 약공격1을 수행한다.
- 피격, 사망, 방 클리어 처리가 정상 동작한다.

## 3. 어쌔신

### 컨셉

어쌔신은 플레이어 뒤로 순간이동한 뒤 공격하는 기습형 몬스터다. 텔레포트 자체는 위협적이지만, 공격 전 짧은 전조를 둬서 불합리한 피격을 줄인다.

### 동작 흐름

```text
Idle
 -> Detect Player
 -> Approach or Wait
 -> Teleport Ready?
      yes -> TeleportBehindPlayer -> PreAttack -> Attack -> Recover -> TeleportCooldown
      no  -> Approach or Strafe
```

### 구현 포인트

- 플레이어의 바라보는 방향 또는 최근 이동 방향을 기준으로 후방 위치를 계산한다.
- 텔레포트 후보 위치가 벽, 방 밖, 충돌 불가 위치라면 대체 위치를 탐색한다.
- 텔레포트 직후 공격 전조를 짧게 표시한다.
- 연속 텔레포트를 막기 위한 쿨타임을 둔다.
- 텔레포트 실패 시 일반 접근 또는 대기 상태로 자연스럽게 복귀한다.

### 완료 조건

- 어쌔신이 플레이어 후방으로 텔레포트한다.
- 벽 안, 방 밖, 플레이 불가능 위치로 텔레포트하지 않는다.
- 텔레포트 후 공격 판정이 정상 동작한다.
- 공격 타이밍이 플레이어에게 시각적으로 인지 가능하다.

## 4. 엘리트 스켈레톤

### 컨셉

엘리트 스켈레톤은 일반 스켈레톤보다 강한 근접형 엘리트 몬스터다. 약공격과 중공격을 조합해 플레이어에게 거리 조절과 회피를 요구한다.

### 동작 흐름

```text
Idle
 -> Detect Player
 -> Approach
 -> In Attack Range?
      yes -> Select Attack
              -> LightAttack1
              -> HeavyAttack1
      no  -> Approach 유지
```

### 구현 포인트

- 약공격은 빠르고 짧은 공격으로 구성한다.
- 중공격은 선딜과 전조를 가진 강한 공격으로 구성한다.
- 중공격 중에는 이동을 제한한다.
- 기존 `TelegraphedAreaAttackController` 또는 커스텀 히트박스 방식 중 구현 비용이 낮은 쪽을 선택한다.
- 엘리트 몬스터로 체감되도록 체력, 공격력, 패턴 빈도를 일반형보다 높인다.

### 완료 조건

- 엘리트 스켈레톤이 정상 스폰된다.
- 약공격과 중공격을 모두 사용한다.
- 중공격은 일반 공격보다 위협적이지만 회피 가능한 전조가 있다.
- 사망 및 방 클리어 처리가 정상 동작한다.

## 5. 스켈레톤 메이지

### 컨셉

스켈레톤 메이지는 원거리 마법 공격을 사용하는 엘리트 몬스터다. 근접 몬스터와 함께 등장했을 때 플레이어의 우선 타겟 판단을 유도한다.

### 동작 흐름

```text
Idle
 -> Detect Player
 -> Keep Distance
 -> Cast Ready?
      yes -> CastTelegraph -> FireMagic -> Recover -> Cooldown
      no  -> Keep Distance
```

### 구현 포인트

- 기존 `ProjectileWeapon` 또는 별도 마법 투사체를 사용한다.
- 원거리 공격 데미지는 `EnemyData`의 `Projectile` 타입으로 관리한다.
- 플레이어와 너무 가까워지면 후퇴하는 AI를 구성한다.
- 공격 전 시전 모션 또는 전조를 표시한다.
- 투사체 풀링, 충돌 레이어, 데미지 적용이 기존 적과 동일하게 동작하는지 확인한다.

### 완료 조건

- 스켈레톤 메이지가 정상 스폰된다.
- 플레이어를 감지하면 원거리 마법 공격을 사용한다.
- 공격 전조가 시각적으로 확인된다.
- 근접형 몬스터와 섞여도 전투 흐름이 깨지지 않는다.

   - 원본 에셋을 직접 수정하지 않고 `_Project` 하위 프리팹과 애니메이션으로 구성한다.

2. 공통 데이터 생성
   - `EnemyData_Bat`

5. 카탈로그 등록
   - `EnemyCatalog_Default`에 신규 enemyId, prefab, data를 연결한다.

7. 2스테이지 RoomData 반영
   - 기본몹 웨이브 구성

## 테스트 계획

- 각 몬스터 단독 스폰 테스트
- `EnemyData` 수치 런타임 반영 테스트
- 플레이어 감지, 접근, 공격 전환 테스트
- 피격, 사망, 방 클리어 카운트 테스트
- 미니맵 표시 테스트
- 2스테이지 RoomData 웨이브 스폰 테스트
- 박쥐 벽/장애물 충돌 테스트
- 어쌔신 텔레포트 후보 위치 검증
- 스켈레톤 메이지 투사체 충돌 및 데미지 검증
- 기본 몬스터와 엘리트 몬스터 혼합 전투 테스트

## 주요 리스크

- 박쥐의 장애물 무시 이동이 기존 물리 레이어 정책과 충돌할 수 있다.
- 어쌔신 텔레포트 위치가 벽 안, 방 밖, 플레이 불가능 지점으로 잡힐 수 있다.
- 스켈레톤 메이지 투사체 풀링과 데미지 적용이 기존 `EnemyDataRuntimeAdapter` 흐름과 맞지 않을 수 있다.
- 엘리트 스켈레톤의 중공격 전조가 부족하면 불합리하게 느껴질 수 있다.
- 2스테이지 몬스터 수와 엘리트 등장 비율이 과하면 난이도 상승 폭이 커질 수 있다.

## 완료 기준

- 신규 몬스터 5종이 각각 프리팹과 `EnemyData`를 가진다.
- `EnemyCatalog_Default`에서 enemyId로 조회 가능하다.
- RoomData에 배치하면 던전 스포너에서 정상 생성된다.
- 모든 몬스터가 피격, 사망, 방 클리어 조건에 정상 반영된다.
- 2스테이지 테스트 방에서 기본몹과 엘리트 조합 전투가 가능하다.
- 외부 에셋 원본을 직접 수정하지 않았다.
