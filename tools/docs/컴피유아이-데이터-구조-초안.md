## 1. 설계 방향

- 내부 사용자 2~3명, 1주 MVP 기준
- DB는 SQLite 고정
- 핵심 축은 `사용자`, `워크플로우 스냅샷`, `생성 결과`, `로그`
- ComfyUI 개념에 맞춰 `workflow JSON`과 `prompt JSON`을 구분해 저장 가능하게 설계
- 이미지 원본은 S3에 저장하고, DB는 조회용 메타데이터와 연결 정보를 저장
- `/prompt -> prompt_id -> /history/{prompt_id}` 흐름을 generation 단위로 추적 가능해야 한다

## 3. 테이블 상세

### 3.1 `users`

사용자 로그인 및 기본 정보 저장용 테이블

| 컬럼 | 타입 예시 | 설명 |
|---|---|---|
| id | INTEGER PK | 사용자 기본 키 |
| username | TEXT UNIQUE | 로그인 계정명 |
| password_hash | TEXT | 비밀번호 해시 |
| display_name | TEXT | 화면 표시 이름 |
| role | TEXT | 관리자 / 일반 사용자 |
| is_active | INTEGER | 활성 여부 |
| created_at | DATETIME | 계정 생성 시각 |
| last_login_at | DATETIME | 최근 로그인 시각 |

역할:

- 앱 로그인 처리
- 생성자 필터 기준
- 관리자/일반 사용자 구분

---

### 3.2 `workflow_snapshots`

ComfyUI 노드 그래프와 관련 메타를 저장하는 테이블

| 컬럼 | 타입 예시 | 설명 |
|---|---|---|
| id | INTEGER PK | 워크플로우 스냅샷 ID |
| created_by | INTEGER FK -> users.id | 저장한 사용자 |
| workflow_name | TEXT | 워크플로우 이름 |
| workflow_version | TEXT | 워크플로우 버전 |
| workflow_json | TEXT | 전체 워크플로우 JSON |
| model_name | TEXT | 대표 모델명 |
| notes | TEXT | 적용 LoRA / 실험 메모 |
| created_at | DATETIME | 저장 시각 |

역할:

- 재현 가능한 워크플로우 스냅샷 보관
- workflow JSON 다운로드의 원본 데이터
- 기본 모델명과 적용 LoRA 메모의 최소 기록 지점
- 같은 워크플로우로 여러 generation이 연결될 수 있음

---

### 3.3 `generations`

생성 실행 1건 자체를 기록하는 테이블

| 컬럼 | 타입 예시 | 설명 |
|---|---|---|
| id | INTEGER PK | 생성 실행 ID |
| created_by | INTEGER FK -> users.id | 실행 사용자 |
| workflow_snapshot_id | INTEGER FK -> workflow_snapshots.id NULL | 사용한 워크플로우 스냅샷 |
| prompt_id | TEXT UNIQUE | ComfyUI `/prompt` 응답으로 받은 ID |
| prompt_summary | TEXT | 조회용 프롬프트 요약 |
| prompt_json | TEXT | 실제 실행에 사용된 prompt 구조 |
| full_prompt | TEXT | 상세 페이지 접이식 표시용 원문 |
| status | TEXT | queued / running / success / failed / upload_failed / metadata_failed |
| failed_stage | TEXT NULL | generate / upload / metadata 등 실패 단계 |
| generator_host | TEXT | 어느 추론 장비에서 실행했는지 |
| started_at | DATETIME | 생성 시작 시각 |
| finished_at | DATETIME | 생성 종료 시각 |
| error_message | TEXT | 실패 시 에러 메시지 |
| created_at | DATETIME | 생성 요청 생성 시각 |

역할:

- 생성 요청 1건의 상태 추적
- `prompt_id`와 결과를 연결
- 성공/실패/업로드 상태 관리
- 관리자 실패 확인 페이지의 핵심 데이터

규칙:

- `prompt_id`는 ComfyUI history 조회와 동기화의 기준 키다.
- `prompt_summary`는 목록 페이지에서 바로 보여줄 수 있는 짧은 값으로 유지한다.
- `full_prompt`는 상세 페이지에서 접이식으로 보여주거나 복구용으로 활용한다.
- `failed_stage`는 실패 지점 추적을 쉽게 하기 위한 필드다.

---

### 3.4 `generation_outputs`

실제 이미지 결과 파일과 연결되는 테이블

| 컬럼 | 타입 예시 | 설명 |
|---|---|---|
| id | INTEGER PK | 출력 파일 ID |
| generation_id | INTEGER FK -> generations.id | 어떤 generation의 결과인지 |
| image_url | TEXT | S3 원본 이미지 경로 |
| file_name | TEXT | 파일명 |
| file_size | INTEGER | 파일 크기 |
| mime_type | TEXT | 이미지 포맷 |
| width | INTEGER | 가로 크기 |
| height | INTEGER | 세로 크기 |
| created_at | DATETIME | 업로드 시각 |

역할:

- S3 원본 이미지 참조
- 상세 페이지 이미지 출력
- 다운로드 기능 연결

규칙:

- `image_url`은 S3 원본 접근 기준 경로를 저장한다.
- 다중 결과 이미지 가능성을 고려해 `generation_id` 기준 1:N 구조를 유지한다.

---

### 3.5 `audit_logs`

운영/디버깅 로그용 테이블

| 컬럼 | 타입 예시 | 설명 |
|---|---|---|
| id | INTEGER PK | 로그 ID |
| user_id | INTEGER FK -> users.id NULL | 관련 사용자 |
| action_type | TEXT | login / generate / upload / download 등 |
| target_type | TEXT | users / generations / outputs 등 |
| target_id | INTEGER | 대상 데이터 ID |
| status | TEXT | success / failed / warning |
| message | TEXT | 상세 로그 또는 오류 메시지 |
| created_at | DATETIME | 로그 시각 |

역할:

- 관리자용 실패 확인 페이지
- 생성 실패, 업로드 실패, 로그인 실패 추적
- 운영 이슈 기록

규칙:

- 최소한 로그인, 생성, 업로드, 다운로드 이벤트는 남긴다.
- 실패 로그는 원인 파악 가능한 메시지를 포함한다.
- `target_type + target_id` 조합으로 관련 대상을 역추적할 수 있게 한다.

## 4. 관계 요약

### 관계

- `users 1:N workflow_snapshots`
- `users 1:N generations`
- `workflow_snapshots 1:N generations`
- `generations 1:N generation_outputs`
- `users 1:N audit_logs`

### 설명

- 한 사용자는 여러 워크플로우 스냅샷을 저장할 수 있다
- 한 사용자는 여러 generation을 실행할 수 있다
- 하나의 workflow snapshot은 여러 generation에서 재사용될 수 있다
- 하나의 generation은 하나 이상 output을 가질 수 있다
- 로그는 사용자와 특정 대상 데이터를 연결할 수 있다

## 6. 최소 SQL 초안

```sql
CREATE TABLE users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    username TEXT NOT NULL UNIQUE,
    password_hash TEXT NOT NULL,
    display_name TEXT NOT NULL,
    role TEXT NOT NULL DEFAULT 'USER',
    is_active INTEGER NOT NULL DEFAULT 1,
    created_at DATETIME NOT NULL,
    last_login_at DATETIME
);

CREATE TABLE workflow_snapshots (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    created_by INTEGER NOT NULL,
    workflow_name TEXT NOT NULL,
    workflow_version TEXT,
    workflow_json TEXT NOT NULL,
    model_name TEXT,
    notes TEXT,
    created_at DATETIME NOT NULL,
    FOREIGN KEY (created_by) REFERENCES users(id)
);

CREATE TABLE generations (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    created_by INTEGER NOT NULL,
    workflow_snapshot_id INTEGER,
    prompt_id TEXT UNIQUE,
    prompt_summary TEXT,
    prompt_json TEXT,
    full_prompt TEXT,
    status TEXT NOT NULL,
    failed_stage TEXT,
    generator_host TEXT,
    started_at DATETIME,
    finished_at DATETIME,
    error_message TEXT,
    created_at DATETIME NOT NULL,
    FOREIGN KEY (created_by) REFERENCES users(id),
    FOREIGN KEY (workflow_snapshot_id) REFERENCES workflow_snapshots(id)
);

CREATE TABLE generation_outputs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    generation_id INTEGER NOT NULL,
    image_url TEXT NOT NULL,
    file_name TEXT,
    file_size INTEGER,
    mime_type TEXT,
    width INTEGER,
    height INTEGER,
    created_at DATETIME NOT NULL,
    FOREIGN KEY (generation_id) REFERENCES generations(id)
);

CREATE TABLE audit_logs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER,
    action_type TEXT NOT NULL,
    target_type TEXT NOT NULL,
    target_id INTEGER,
    status TEXT NOT NULL,
    message TEXT,
    created_at DATETIME NOT NULL,
    FOREIGN KEY (user_id) REFERENCES users(id)
);
```

## 7. 현재 프로젝트 기준 확정 사항

- DB는 SQLite 고정
- 결과 이미지는 S3 저장
- workflow JSON 다운로드 허용
- full prompt는 상세 페이지 접이식 표시
- 실패 결과도 목록에 표시
- 관리자용 실패 페이지는 별도 운영
- `prompt_id`는 generation 단위 추적 키로 포함
- 상태값은 API 문서와 맞춰 `queued/running/success/failed/upload_failed/metadata_failed` 기준으로 정리
- `model_name`은 기본 모델명 기준으로 두고, 적용 LoRA는 우선 `notes`에 메모한다
