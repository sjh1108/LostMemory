# 컴피유아이 1차 MVP 에픽 기준 진행안

## 문서 목적

이 문서는 `컴피유아이-1차-mvp-통합-작업표.csv`를 어떤 순서와 묶음으로 진행할지 설명하는 가이드다.

이번 버전은 에픽을 너무 크게 묶지 않고, 그렇다고 과하게 잘게도 나누지 않는 중간 수준으로 정리한다.

기준 에픽은 아래 8개다.

- Epic A. 범위 / 운영 기준
- Epic B. 공용 ComfyUI 서버화
- Epic C. ComfyUI API 실측
- Epic D. AI 도구 백엔드 구축
- Epic E. 저장 / 메타데이터
- Epic F. 결과 조회 / 히스토리
- Epic G. 인증 / 운영
- Epic H. 통합 검증 / 데모

즉, 회의나 계획은 에픽 단위로 보고, 실제 실행은 통합 작업표의 작업코드와 `차수` 기준으로 따라간다.

이번 버전에서 추가로 고정한 운영 기준은 아래 네 가지다.

- `컴피유아이-1차-mvp-통합-작업표.csv`를 메인 작업표로 사용한다.
- 통합 작업표의 상세 작업 담당자는 전부 `AI1`이다.
- 상위 작업코드는 `AI-001`, `AI-101`, `AI-201`처럼 범위가 달라질 때 100단위로 끊는다.
- 세부 작업은 `AI-201-01`, `AI-203-05`, `AI-701-02`처럼 상위 작업 아래 독립 코드로 관리한다.

차수 기준은 아래처럼 본다.

- `사전 정리`: 이미 확인된 실험, 실행, 문서 기반
- `1차`: 생성 -> 저장 -> 조회가 실제로 한 번 돌아가는 최소 작동 범위
- `2차`: 공개 주소, 보호, 실패 처리, 인증, 안정화
- `3차`: 운영 polish, 데모 준비, runbook, 추가 편의 기능

## 지금 기준 상태

이미 되어 있는 것:

- `tools/ComfyUI` 로컬 작업공간 반입
- `.venv_local` 기반 실행 구조
- `start_comfyui.cmd` 기준 로컬 실행
- 최소 1회 이상 generation 성공
- output 이미지와 실행 로그 확인
- SD1.5 체크포인트 및 일부 LoRA 반입
- 실행 문서, 운영 가이드, API 초안, 작업 CSV 작성

아직 안 된 것:

- 공용 주소로 ComfyUI UI 공개
- Nginx Reverse Proxy 실제 구성
- HTTPS와 Basic Auth 실제 적용
- `/prompt`, `/history` 샘플 JSON 정리
- AI 도구 백엔드 구현
- S3 업로드와 SQLite 메타데이터 저장
- 결과 목록/상세/다운로드 화면
- 앱 로그인
- end-to-end 통합 검증

## 에픽별 역할

### Epic A. 범위 / 운영 기준

이 에픽은 작업 전에 운영 기준을 고정하는 묶음이다.

주요 내용:

- AI1 단일 담당 기준 확정
- 문서 갱신 위치 정리
- CSV 상태 판정 기준 정리
- 세션 종료 시 문서 갱신 순서 정리

왜 필요한가:

- 이 기준이 없으면 CSV만 커지고 실제 완료 상태가 흐려진다.

완료 기준:

- 이번 1차 MVP 상세 작업이 모두 AI1 기준으로 묶여 있다는 점을 설명 가능하다.
- `CSV -> daily log -> handoff` 같은 갱신 순서가 정리돼 있다.

### Epic B. 공용 ComfyUI 서버화

이 에픽은 로컬에서만 쓰던 ComfyUI를 팀 내부에서 접근 가능한 공용 도구로 바꾸는 묶음이다.

주요 내용:

- GPU 데스크탑 내부 IP와 listen 주소 고정
- output / models / loras 경로 고정
- 기준 workflow, prompt, seed 고정
- Nginx 프록시 구조 작성
- WebSocket 프록시 검증
- 도메인, HTTPS, Basic Auth 적용
- 프록시 주소 기준 생성 smoke test
- ComfyUI 재기동 기준과 실행 스크립트 표준화

핵심 포인트:

- ComfyUI는 `/ws`를 사용하므로 WebSocket 프록시가 반드시 필요하다.
- path 방식보다 subdomain 방식이 안전하다.
- `docker-compose` 초안과 실제 폴더 구조가 어긋난 부분은 먼저 맞춰야 한다.

완료 기준:

- 팀 내부에서 HTTPS 주소로 ComfyUI UI에 접속 가능하다.
- Basic Auth가 걸려 있다.
- 프록시 주소 기준 생성 1회가 성공한다.

### Epic C. ComfyUI API 실측

이 에픽은 백엔드를 붙이기 전에 ComfyUI API를 실제 응답 기준으로 이해하는 묶음이다.

주요 내용:

- `/prompt` 성공 요청 샘플 저장
- `/history/{prompt_id}` 응답 샘플 저장
- prompt_id와 output 파일 매핑 규칙 정리
- workflow 이름과 모델명 추출 규칙 정리
- 실패 샘플 수집
- timeout 기준과 실패 메시지 초안 정리

왜 분리했는가:

- 이 단계가 없으면 백엔드 구현 시 응답 구조를 추측하게 된다.

완료 기준:

- 누구나 같은 샘플 요청을 다시 보내고 같은 응답 구조를 해석할 수 있다.

### Epic D. AI 도구 백엔드 구축

이 에픽은 ComfyUI를 서버에서 호출할 수 있게 만드는 묶음이다.

주요 내용:

- AI 도구 백엔드 위치 확정
- health endpoint와 공통 응답 포맷
- 환경변수와 profile 구조 정리
- 생성 요청 API
- `/prompt` 요청 조립 서비스
- `/history` 폴링과 상태 판정
- timeout / failed 처리
- raw logging 지점
- 환경변수 누락 시 fail-fast 검증

초기 구현 원칙:

- 처음부터 복잡한 큐 구조를 넣지 않는다.
- 한 요청이 끝까지 도는 최소 흐름을 먼저 만든다.
- raw logging을 남겨 실패 분석이 가능하게 한다.

완료 기준:

- 백엔드가 prompt_id를 받고 success / failed / timeout을 판단할 수 있다.

### Epic E. 저장 / 메타데이터

이 에픽은 생성 결과를 남기고 추적할 수 있게 만드는 묶음이다.

주요 내용:

- SQLite 초기화 방식과 DB 파일 위치 정리
- users / workflow_snapshots / generations / generation_outputs / audit_logs 스키마 확정
- generation 시작 시 메타데이터 저장
- workflow snapshot 저장
- output 파일 탐색
- S3 업로드
- image_url과 상태 갱신
- 인덱스 검토
- output 파일 보존 정책
- 업로드 재시도 / 수동 복구 기준
- 업로드 전 파일 존재 / 크기 / 확장자 검증

핵심 포인트:

- 이 에픽은 이미지 파일 저장뿐 아니라 나중에 다시 조회할 수 있는 메타데이터 구조까지 포함한다.
- S3 정책과 SQLite 운영 메모를 같이 정리해두는 편이 좋다.

완료 기준:

- 생성 결과 1건이 DB와 S3에 모두 반영된다.

### Epic F. 결과 조회 / 히스토리

이 에픽은 저장된 결과를 다시 보는 흐름을 만드는 묶음이다.

주요 내용:

- 목록 조회 API
- 상세 조회 API
- 생성자 필터
- 이미지 다운로드
- workflow JSON 다운로드
- 목록 화면
- 상세 화면
- 상태 배지 표
- 로딩 / 빈 상태 / 에러 UI
- full prompt 접이식 UI
- 다운로드 권한 및 만료 정책

핵심 포인트:

- 목록은 빠르게 훑는 용도다.
- 상세는 디버깅과 재현에 필요한 정보를 주는 용도다.

완료 기준:

- 브라우저에서 목록과 상세를 확인하고 파일을 다운로드할 수 있다.

### Epic G. 인증 / 운영

이 에픽은 내부 도구로서 최소한의 보호와 운영 규칙을 붙이는 묶음이다.

주요 내용:

- 앱 로그인 방식 결정
- 로그인 API와 보호 라우트
- 실패 로그 목록 API 또는 화면
- 공용 모델 / preset / LoRA 이름 규칙
- Git 제외 정책
- 결과 이미지 보존 정책
- 초기 사용자 whitelist 또는 seed 기준

핵심 포인트:

- Basic Auth는 외부 차단용이다.
- 앱 로그인은 사용자 식별용이다.
- 둘을 같은 문제로 취급하면 안 된다.

완료 기준:

- 로그인하지 않은 사용자는 결과 조회에 접근하지 못한다.
- 최근 실패를 최소한의 화면이나 API로 확인할 수 있다.

### Epic H. 통합 검증 / 데모

이 에픽은 앞선 에픽들을 한 번에 검증하고 데모 가능한 상태로 묶는 단계다.

주요 내용:

- end-to-end 시나리오 작성
- 테스트 계정 / workflow / 버킷 준비
- 통합 검증 실행
- 실패 케이스 실험
- audit log와 상태 일치 검증
- smoke checklist 작성
- 장애 runbook 작성
- handoff와 종료 절차 정리
- 데모용 계정 / 프롬프트 / 결과물 고정

완료 기준:

- `도메인 접속 -> Basic Auth -> 로그인 -> 생성 -> 업로드 -> DB 기록 -> 목록 -> 상세 -> 다운로드`가 한 번에 재현된다.

## 실제 진행 순서

추천 순서는 아래와 같다.

1. Epic A
2. Epic B
3. Epic C
4. Epic D
5. Epic E
6. Epic F
7. Epic G
8. Epic H

이 순서를 추천하는 이유:

- 공용 ComfyUI가 안정화되지 않으면 백엔드가 붙을 대상이 흔들린다.
- API 샘플이 정리되지 않으면 백엔드 파서가 추측에 의존한다.
- 저장이 안 되면 조회 화면은 붙여도 볼 데이터가 없다.
- 인증은 생성/조회 흐름이 붙은 뒤에 얹는 편이 덜 흔들린다.
- 통합 검증은 마지막에 해야 어디가 비었는지 선명하게 보인다.

## 초보자 기준 첫 실행 순서

가장 먼저 할 5묶음만 고르면 아래가 좋다.

1. 통합 작업표에서 `차수 = 1차`만 먼저 본다.
   - `사전 정리`와 `2차`, `3차`는 잠시 내려두고 실제로 돌아가는 최소 흐름만 잡는다.

2. Epic E의 최소 런타임과 기준 workflow
   - `AI-201-01 ~ AI-201-04`
   - `AI-202-01 ~ AI-202-03`

3. Epic F의 API 샘플 확보
   - `AI-301-01 ~ AI-303-02`

4. Epic G의 최소 백엔드 뼈대
   - `AI-401` ~ `AI-405`의 `차수 = 1차` 상세 작업

5. Epic H / I / K의 최소 저장·조회·검증
   - `AI-501`, `AI-502`, `AI-503`, `AI-505 ~ AI-508`의 `차수 = 1차` 상세 작업
   - `AI-601`, `AI-602`, `AI-604`, `AI-606`, `AI-607`의 `차수 = 1차` 상세 작업
   - `AI-801-01 ~ AI-801-03`
여기까지 끝나면 1차 기준 생성 -> 저장 -> 조회 최소 흐름이 닫힌다. 그다음부터 Reverse Proxy, HTTPS, Basic Auth, 로그인, 운영 polish를 2차와 3차로 넘기면 된다.

## CSV를 보는 방법

통합 작업표는 아래처럼 읽으면 된다.

- 에픽: 큰 묶음
- 차수: 지금 당장 해야 하는지, 뒤로 빼도 되는지 판단하는 기준
- 영역: 실제 담당 범위
- 작업코드: 추적 기준
- 선행작업: 바로 전 단계 확인용

작업코드 해석 예시:

- `AI-201`
  - 1차 MVP 상위 작업
- `AI-201-03`
  - `AI-201` 상위 작업 아래의 세 번째 상세 작업
- `AI-701-02`
  - 인증 / 운영 범위의 두 번째 상세 작업

권장 운영 방식:

- 회의할 때는 에픽 기준으로 본다.
- 실제 개발할 때는 작업코드 기준으로 본다.
- 세션 종료 전에는 `완료여부`와 `상태`를 갱신한다.

## 한 줄 결론

이번 1차 MVP는 `workflow 공유 플랫폼`을 먼저 만드는 작업이 아니다.

먼저 안정적으로 닫아야 하는 흐름은 아래다.

`공용 ComfyUI 접속 -> 생성 실행 -> S3 저장 -> 메타데이터 기록 -> 결과 조회`

에픽은 8개 수준으로 나누고, 실제 구현은 통합 작업표에서 `차수 = 1차`를 먼저 닫은 뒤 `2차`, `3차`로 넓혀가면 된다.
