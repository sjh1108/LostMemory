## 1. 프로젝트 개요

LostMemory 는 3D 협동 로그라이크 액션 게임입니다. 1\~4 명의 플레이어가 절차적으로 생성된 던전을 진행하며 적과 보스를 협력해 처치합니다. Unity 클라이언트가 자체 Relay (Netty 기반 UDP 7777) 를 통해 매칭 후 P2P 동기화 트래픽을 주고받고, 게임 진행 결과는 Spring Boot REST 백엔드의 PostgreSQL 에 저장됩니다.

운영 인프라는 SSAFY EC2 두 대로 구성되어 있고, AI 이미지 생성은 외부 GPU 데스크톱(또는 RunPod) 의 ComfyUI 가 담당합니다.

### 1.1 운영 토폴로지

| 호스트 | 역할 | 도메인 | 주요 stack |
|---|---|---|---|
| **EC2#1 — `k14c201.p.ssafy.io`** | 게임 서버 (REST + UDP Relay) + Jenkins | `https://k14c201.p.ssafy.io` (HTTPS) + UDP/7777 | `server/docker-compose.yml` — postgres / redis / app / relay / nginx (+ certbot 프로필) |
| **EC2#2 — `lostmemory.duckdns.org`** | 게임 공식 사이트(CMS) + AI 도구 인프라 | `https://lostmemory.duckdns.org` (CMS · AI 백엔드), `https://comfyui-lostmemory.duckdns.org` (ComfyUI proxy) | `website/docker-compose.yml`, `tools/infra/docker-compose.yml` |
| **외부 GPU 데스크톱 또는 RunPod** | ComfyUI (이미지 생성) + vLLM (Bllossom-8B LLM) | EC2#2 의 nginx 가 reverse proxy 로 노출 | host 직접 실행 (Docker 의존 X) |

### 2.1 로컬 개발 부트스트랩

```bash
# 1) 저장소 클론
git clone https://lab.ssafy.com/s14-final/S14P31C201.git
cd S14P31C201

# 2) 게임 백엔드 로컬 개발 (postgres + redis 만 컨테이너, app 은 IDE 에서 bootRun)
cd server
cp .env.dev.example .env
docker compose -f docker-compose.dev.yml --env-file .env up -d postgres redis
./gradlew bootRun                     # ServerApplication (REST 18080)
./gradlew bootRun \
    --args='--spring.main.sources=com.lostmemory.relay.RelayApplication'   # RelayApplication (UDP 7777)

# 3) CMS 로컬 개발
cd ../website
cp .env.example .env && vi .env
docker compose --env-file .env up -d cms-postgres
cd backend && ./gradlew bootRun

# 4) Unity 클라이언트
# client/LostMemory/LostMemory.sln 을 Unity 6 LTS 로 오픈
```

## 6. 배포 시 특이사항

운영 환경에서 처음 stack 을 띄울 때 흔히 막히는 지점을 정리합니다.

### 6.1 게임 서버: 한 이미지 두 entrypoint

`server/docker-compose.yml` 의 `app` 과 `relay` 두 서비스는 **동일한 `server-app:latest` 이미지**를 사용합니다. Spring Boot 의 `PropertiesLauncher` 를 통해 `relay` 컨테이너만 main class 를 override 합니다.

```yaml
relay:
  image: server-app:latest
  entrypoint: ["sh","-c","exec java $$JAVA_OPTS -cp /app \
    -Dloader.main=com.lostmemory.relay.RelayApplication \
    org.springframework.boot.loader.launch.PropertiesLauncher"]
```

`build.gradle` 의 `springBoot { mainClass = 'com.lostmemory.server.ServerApplication' }` 블록이 반드시 있어야 다중 main class 빌드가 성공합니다. `@SpringBootApplication` 어노테이션이 두 개 이상이면 자동 추론은 실패합니다.

### 6.2 UDP 7777 은 nginx 우회

기존에는 nginx `stream {}` 블록으로 UDP 를 proxy 했으나, Let's Encrypt 인증서 reload 시 세션이 끊겨 게임 도중 disconnect 가 발생하는 문제가 있었습니다. 현재는 `relay` 컨테이너가 호스트 포트 `7777/udp` 를 직접 publish 하고 nginx 를 거치지 않습니다.

EC2 보안그룹에서 **UDP 7777 inbound 허용**이 반드시 필요합니다. UFW (호스트 방화벽) 사용 시에도 동일.

### 6.3 envvar 기본값 미사용 정책

`application.yaml` 의 모든 `${VAR}` 는 default fallback (`${VAR:default}`) 을 쓰지 않습니다. 키 누락 시 `BindException` 으로 즉시 부팅 실패하여 운영 누락 사고를 차단합니다.

특히 `JwtProperties` (record 4 필드 — `secret`, `accessExpiration`, `refreshExpiration`, `sessionExpiration`) 는 네 개 모두 채워야 부팅 성공합니다. `relay` 컨테이너도 동일하게 모두 필요합니다.

### 6.4 Jenkins credential `lostmemory-env`

`server/Jenkinsfile` 은 Secret file 타입 credential `lostmemory-env` 를 `ENV_FILE` 환경변수로 받습니다. Jenkins UI 의 **Replace** 체크박스를 명시적으로 활성화해야 기존 파일이 새 내용으로 갱신됩니다.

```groovy
environment {
  ENV_FILE = credentials('lostmemory-env')
  GIT_LFS_SKIP_SMUDGE = '1'   # 서버 빌드에 LFS 바이너리 불필요
}
```

`.env` 변경 시 EC2 호스트의 `/home/ubuntu/lostmemory/server/.env` 와 Jenkins credential 둘 다 갱신해야 합니다.

### 6.5 `.env` 파일 함정 (CRLF / 마지막 newline / dash)

운영 EC2 의 `/bin/sh` 는 dash 입니다. `.` (source) 명령이 PATH 만 인식하므로 `.env` 를 `set -a && . .env` 형태로 source 할 때 주의가 필요합니다. 또한:

- Windows 에서 작성된 `.env` 의 CRLF lineending 은 `sed` / `source` 를 깨뜨립니다. 운영 EC2 에 올리기 전 `dos2unix` 로 정규화.
- `.env` 의 마지막 라인에 newline 이 없으면 마지막 키가 무시될 수 있습니다.
- nano / vi 로 편집 시 `<...>` 같은 angle bracket 글자가 그대로 남는 흔한 실수가 있으므로 push 전 `grep -E '<|>' .env` 로 sanity 확인.

### 6.6 Hibernate ddl-auto

운영 (`application-prod.yml`) 은 `ddl-auto: validate` 입니다. entity 추가 또는 컬럼 변경 시 schema validation 이 실패하면서 부팅이 fail 됩니다.

스키마 변경은 다음 절차로 진행합니다.

1. 백엔드 담당자가 entity / migration SQL 같이 작성한 PR 생성
2. EC2 에서 미리 SQL 수동 적용 (또는 Flyway 기반으로 별도 마이그레이션)
3. PR 머지 + 자동 배포 → ddl-auto=validate 통과

응급 상황에서 ALTER/CREATE 임시 박는 패턴은 [`docs/runbook-db-backup.md`](../docs/runbook-db-backup.md) 와 [`server/docs/01_data_persistence_schema_run_result_strategy.md`](../server/docs/01_data_persistence_schema_run_result_strategy.md) 를 참조하십시오.

### 6.7 cgroup v2 호환 cAdvisor

EC2 Ubuntu 22.04 는 cgroup v2 가 기본이므로 cAdvisor 컨테이너 마운트가 v1 과 다릅니다. `server/docker-compose.monitoring.yml` 의 cadvisor 서비스는 `/sys/fs/cgroup:/sys/fs/cgroup:ro` 만 마운트합니다 (v1 시절의 `/sys/fs/cgroup:/sys/fs/cgroup:ro` + `/cgroup:/cgroup:ro` 이중 마운트 X).

### 6.8 RunPod vLLM POD_ID 갱신

RunPod 의 POD 가 재기동되면 URL 의 `<POD_ID>` 가 변경됩니다. `.env` 의 `VLLM_BASE_URL` 을 갱신하고 게임 백엔드 재기동 (`docker compose --env-file .env up -d --force-recreate app`) 이 필요합니다.


마이그레이션 파일 목록 (`website/backend/src/main/resources/db/migration/`):

- `V1__create_admin_user.sql`
- `V2__create_notice.sql`

- `V4__create_faq.sql`
- `V5__patch_note_add_download_url.sql`
- `V6__create_faq_category.sql`
- `V7__create_feedback.sql`

이후 `AdminSeedRunner` 가 `.env` 의 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 로 admin 계정 1 개를 BCrypt 해시하여 insert 합니다 (이미 존재하면 skip).

### 7.3 운영 백업 / 복원

자동 백업은 `server/scripts/db-backup.sh` (매일 02:30 cron). 상세 절차는 [`docs/runbook-db-backup.md`](../docs/runbook-db-backup.md) 참조.

```bash
# 수동 백업
docker compose --env-file .env exec -T postgres \
  sh -c 'PGPASSWORD="$POSTGRES_PASSWORD" pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" \
    --clean --if-exists --no-owner --no-privileges' \
  | gzip -9 > /home/ubuntu/lostmemory/backups/manual-$(date +%F).sql.gz

# 복원
gunzip -c /home/ubuntu/lostmemory/backups/<백업.sql.gz> \
  | docker compose --env-file .env exec -T postgres psql -U appuser -d appdb
```

## 8. 시연 시나리오

### 8.1 게임 (Unity 클라이언트)

1. **빌드 산출물 수령**: Unity Editor 의 Build Settings 에서 Windows / macOS 빌드 산출물 (`LostMemory.exe` 등) 을 평가 위원께 전달합니다. (운영 EC2 에는 클라이언트 빌드 산출물이 없습니다.)
2. **로그인**: 클라이언트 실행 후 이메일 + 비밀번호로 로그인. 백엔드 `POST /api/auth/login` 호출 → access token + refresh token 발급.
3. **방 생성 / 입장**: 호스트가 방 생성 (`POST /api/sessions`) → 6자리 join code 발급. 다른 플레이어가 같은 코드로 join (`POST /api/sessions/{code}/join`).
4. **Relay 매칭**: 클라이언트가 백엔드로부터 단명 session token (TTL 10분) 을 받아 UDP 7777 의 RelayHandler 에 핸드셰이크.
5. **인게임 플레이**: 던전 진입 → 룸 클리어 → 다음 룸 → 보스 → 클리어 / 사망. 진행 상황은 백엔드에 saving point 마다 persist.
6. **사후 데이터 확인**: 백엔드 `GET /api/runs/{id}` 로 게임 결과 조회. CMS 의 패치노트 페이지에서도 최근 빌드 확인 가능.

### 8.2 CMS 사이트

1. **공식 사이트 접속**: `https://lostmemory.duckdns.org/` → 공지 / 패치노트 / FAQ / 피드백 (Thymeleaf 서버 사이드 렌더링).
2. **Admin 로그인**: `https://lostmemory.duckdns.org<ADMIN_BASE_PATH>/login` (obscure path, `.env` 의 `ADMIN_BASE_PATH` 값) → AdminSeedRunner 가 seed 한 계정으로 로그인.
3. **콘텐츠 작성**: 공지 / 패치노트 / FAQ 카테고리·항목 CRUD. Markdown 본문은 commonmark + jsoup 으로 렌더링.
4. **피드백 수신**: 사용자가 사이트 폼으로 제출한 피드백을 admin 페이지에서 조회.

### 8.3 AI 도구

1. **진입**: `https://lostmemory.duckdns.org/` 의 AI 도구 진입 path. Basic Auth (`/etc/nginx/auth/.htpasswd`) 통과 후 접근.
2. **워크플로 선택**: ComfyUI workflow JSON (`tools/ComfyUI/workflows/*.json`) 중 하나 선택.
3. **AI 백엔드 제출**: `POST /api/generations` → ai_server 가 ComfyUI 의 `/prompt` 엔드포인트에 작업 등록 + history poll.
4. **결과 다운로드**: 완료된 이미지가 AWS S3 에 업로드 → signed URL (TTL `S3_SIGNED_URL_TTL_SECONDS`) 반환 → 다운로드.

### 10.1 배포 / 롤백 / 상태 조회

`server/scripts/deploy.sh` 가 단일 진입점입니다. Jenkins 자동 배포와 운영자 수동 운영이 같은 스크립트를 사용합니다.

```bash
cd /home/ubuntu/lostmemory/server

./scripts/deploy.sh rollback <BUILD_NUMBER>   # 이전 버전 image 로 latest 재태깅 + recreate
./scripts/deploy.sh status                    # 현재 컨테이너 상태 + image id
```

배포 실패 시 healthcheck 폴링 (90초) 후 마지막 100줄 로그 출력. 자동 롤백은 하지 않으므로 운영자가 수동 `rollback` 호출. 자세한 절차는 [`docs/runbook-rollback.md`](../docs/runbook-rollback.md) 참조.

### 10.6 자주 발생하는 문제

| 증상 | 원인 / 점검 명령 |
|---|---|
| Spring Boot 부팅 시 `BindException: JwtProperties` | `JWT_*EXPIRATION` 4개 키 중 누락. `.env` 4 라인 확인 |
| Spring Boot 부팅 시 `BindException: AdminProperties` (CMS) | `ADMIN_BASE_PATH` 미설정. obscure path 로 채움 |
| 컨테이너 healthcheck 90초 후 timeout | `docker compose logs --tail=200 app` 으로 실패 원인 확인 → 보통 DB 연결 / migration |
| `Could not resolve host: postgres` | compose 네트워크 share 누락. `docker compose ps` 로 service 가 `backend` 네트워크에 참여 중인지 확인 |
| Let's Encrypt rate limit | 동일 도메인 7일 5회 발급 한도 초과. staging endpoint 로 dry-run 후 prod 진행 |
| UDP 7777 연결 안 됨 | EC2 보안그룹 UDP 7777 inbound 확인 + UFW 확인 + `relay` 컨테이너 ports 매핑 확인 |
| Jenkins build with parameters 가 dev .env 로 인식 | Jenkins credential `lostmemory-env` Replace 체크박스 활성화 후 재upload |

## 부록 B: setup.sh 빠른 실행 가이드

`exec/setup.sh` 는 운영 EC2 0 상태에서 메인 stack 까지 띄우는 idempotent wrapper 입니다. 기존 `server/scripts/*.sh` 를 호출만 하며, 운영 로직을 중복하지 않습니다.

### B.1 빠른 시작

```bash
git clone https://lab.ssafy.com/s14-final/S14P31C201.git ~/lostmemory
cd ~/lostmemory

# 도움말
bash exec/setup.sh --help

# 전체 부트스트랩 (prerequisites → env → game-stack → cert → cms → ai-tool → cron)
bash exec/setup.sh all

# 모니터링 stack 포함
bash exec/setup.sh --with-monitoring all
```

### B.2 subcommand

| step | 동작 | 호출 대상 |
|---|---|---|
| `prerequisites` | docker / compose / openssl / curl / git 설치 검사 (설치는 안 함) | (검사만) |
| `env` | 4세트 `.env` 파일 존재 확인 + 미생성 시 example 에서 복사 + 필수 키 미채움 검출 | (파일 작업만) |
| `game-stack` | 게임 stack 기동 (postgres + redis + app + relay) + healthcheck 폴링 | `server/docker-compose.yml` |
| `cert` | Let's Encrypt 첫 발급 (이미 cert 있으면 skip) | `server/scripts/init-letsencrypt.sh` |
| `cms` | CMS stack 기동 (cms-postgres + website-backend) | `website/docker-compose.yml` |
| `ai-tool` | AI 도구 인프라 nginx + postgres 기동. ai-server 는 host bootRun 안내만 echo | `tools/infra/docker-compose.yml` |
| `monitoring` | `--with-monitoring` 일 때만 prometheus + grafana + alertmanager + node-exporter + cadvisor | `server/docker-compose.monitoring.yml` |
| `cron` | certbot-renew / db-backup / docker-prune cron 라인 안내만 echo (자동 등록 안 함) | (안내만) |
| `all` | 위 순서대로 모두 실행 | |

### B.3 검증 명령

setup.sh `all` 완료 후 다음 명령으로 외부 도달 확인:

```bash
curl -I https://k14c201.p.ssafy.io/api/actuator/health   # 200 + {"status":"UP"}
curl -I https://lostmemory.duckdns.org/                   # 200 (CMS)
curl -I https://lostmemory.duckdns.org/                   # 200 (AI 도구 진입 + Basic Auth 통과 후)
nc -uvz k14c201.p.ssafy.io 7777                          # UDP open
```

### B.4 안전 정책

setup.sh 는 다음 동작을 **하지 않습니다**.

- 볼륨 삭제 (`docker compose down -v`)
- crontab 자동 등록 (echo 안내만)
- git push / force push
- 기존 운영 컨테이너 강제 재생성 (`--force-recreate` 미사용)

destructive 작업이 필요한 경우 운영자가 SSH 직접 명령으로 실행합니다 ([`docs/runbook-rollback.md`](../docs/runbook-rollback.md) 참조).
