# AI 제작 파이프라인

## 목표

팀 내부에서 이미지 생성 플로우를 공유하고, 결과물과 작업 맥락을 함께 축적할 수 있는 ComfyUI 기반 제작 환경을 만든다.

## 현재 상태

- 현재 ComfyUI는 각 작업자의 로컬 PC에서 서버를 띄워 개인 GPU로 실행하고 있다
- 로컬 기반이라 비용 부담이 적고, 자유롭게 플로우를 실험할 수 있다
- 반면 팀원 간 플로우 공유, 결과 재현, 작업 히스토리 축적이 어렵다

## 현재 방식의 장단점

장점:
- 로컬 실행이 가능해 무료에 가깝게 운용 가능
- 이미지 생성이 아니라 플로우 자체를 직접 구성할 수 있어 자유도가 높다

단점:
- 팀 내 공유와 표준화가 어렵다
- 다른 사람의 플로우를 그대로 이어받아 수정하기 어렵다
- 어떤 조건으로 결과물이 나왔는지 추적하기 어렵다

## 1차 목표: 내부 공유 서버

- 팀 내에서 공용으로 접근 가능한 내부 ComfyUI 서버를 구축한다
- 작업자가 개인 로컬 환경 대신 공용 페이지에서 플로우를 확인하고 실행할 수 있게 한다
- 공통 모델, LoRA, 프롬프트 프리셋, 기본 워크플로를 서버 기준으로 관리한다
- 생성 결과를 팀 공용 저장소나 갤러리 형태로 남겨 재사용성을 높인다

## 1차 필수 기능

- 공용 워크플로 열람 및 실행
- 생성 이미지 저장 및 공유
- 기본 메타데이터 기록
- 작업 결과 히스토리 조회
- 공용 리소스 관리 기준 수립

## 2차 목표: 협업 기능 확장

- 동시에 여러 명이 작업하거나 같은 프로젝트를 공유할 수 있게 한다
- 이미지 결과물, 작업 내용, 피드백, 개선 내역을 한 곳에서 관리한다
- 오픈소스 기반 확장을 통해 팀 생산성을 높이는 협업 기능을 붙인다

## 2차 협업 기능 후보

- 프로젝트/작업공간 단위 공유
- 이미지별 코멘트, 태그, 즐겨찾기
- 플로우 버전 관리 및 비교
- 프롬프트/노드 설정 변경 이력 저장
- 결과물 A/B 비교와 채택 이력 기록
- 데이터셋 정리 및 AI 개선 실험 로그 축적

## 운영 원칙

- 게임 서비스용 백엔드와 AI 제작 도구는 배포 단위를 분리한다
- 내부 서버는 팀 생산성 도구로 보고, 게임 런타임 필수 의존성으로 묶지 않는다
- 공유 기능보다 먼저 재현 가능성과 기록 가능성을 확보한다

## 기대 효과

- 아트 레퍼런스와 결과물을 팀이 함께 빠르게 검토할 수 있다
- 개인 로컬 환경에 묶인 플로우를 공용 자산으로 전환할 수 있다
- 추후 AI 개선 작업과 결과 비교가 쉬워져 반복 생산성이 높아진다

## 현재 미정 사항

- 내부 서버의 실제 배포 위치
- GPU 자원 할당 방식
- 권한 관리 범위
- 결과물 저장 정책
