- 문서 목적: 지금까지의 회의/문서/대화에서 발생한 주요 논쟁점과 현재 결정 사항을 정리한다.
- 작성 기준: 최신 대화 기준 우선
- 문서 형식: 분류별 `details` 블록 사용

## 0. 확정 사항

<details>
<summary><strong>1. 인증 / 계정</strong></summary>

- MVP 인증은 **이메일 없이 `loginId + password + nickname` 기반 간단 계정 로그인**으로 진행한다.
- 회원가입 시 입력값은 **`loginId`, `password`, `nickname`** 이다.
- `nickname`은 인게임 표시명으로 사용한다.
- 로그인 상태 유지를 위해 **access token + refresh token** 구조를 유지한다.
- `access token`은 클라이언트 **메모리 저장**을 원칙으로 한다.
- `refresh token`은 클라이언트 **영구 저장소 보관**을 전제로 한다.
- 로그아웃 시에는 **refresh token을 무효화**한다.
- 로그아웃 없이 종료하면 **refresh token을 유지**하여 재로그인 없이 접속할 수 있다.

</details>

<details>
<summary><strong>2. 메타 성장</strong></summary>

- `재능`과 `기억의 파편`은 둘 다 런 외부 시스템이지만 **별개의 존재**다.
- `재능`은 **언제든 초기화 및 재분배 가능한 외부 스탯 분배 시스템**이다.
- `기억의 파편`은 **영구 강화 수단이자 영구 재화**로 사용한다.
- 따라서 `재능 = 재분배 가능한 외부 스탯 분배`, `기억의 파편 = 영구 강화 수단`으로 구분한다.

</details>

<details>
<summary><strong>3. 재화 구조</strong></summary>

- `memoryShards(기억의 파편)`는 **영구 재화**다.
- `gold`는 현재 기준 **인런 재화**다.
- `gold`는 런 내부 상점 구매 등 인런에서 사용하고, 기본 해석은 **런 종료 후 소멸**이다.

</details>

<details>
<summary><strong>4. 유니티 인런 / 백엔드 책임 분리</strong></summary>

- **인런 실시간 상태는 유니티 런타임**이 담당한다.
- **정산 및 저장은 백엔드**가 담당한다.
- 유니티 런타임이 담당하는 예시는 다음과 같다.
  - 현재 체력
  - 현재 gold
  - 현재 보유 유물
  - 방 진행
  - 보상 선택
  - 상점 구매
  - 전투 판정
  - 보스 판정
  - 실시간 멀티 상태
- 백엔드가 담당하는 예시는 다음과 같다.
  - 인증
  - 계정
  - 진행 저장
  - 런 종료 결과 정산
  - 최소 전적/기록 저장
  - memoryShards 누적
  - 영구 성장 저장
- 런 종료 시 백엔드가 최소한 받아야 하는 정보는 **플레이 타임**, **런 결과(`clear`, `death`, `surrender`)** 이다.

</details>

<details>
<summary><strong>5. 멀티플레이 범위</strong></summary>

- **초기 MVP는 1인**
- **1차 목표는 2인 안정화**
- **최종 목표는 4인 안정화**

즉, 최종 비전과 현재 개발 컷을 다음과 같이 구분한다.

- **최종 비전**: 4인 협동
- **현재 개발 목표**: 2인 안정화
- **초기 검증 단계**: 1인

</details>

<details>
<summary><strong>6. 세션 / 런 / 공간 용어</strong></summary>

- `세션`과 `런`은 서로 다른 개념이다.
- `세션`은 **매칭룸 생성부터 매칭룸 제거 또는 폭파 시점까지**의 멀티플레이 연결 단위다.
- `런`은 **던전 입장부터 종료 시점까지**의 실제 플레이 세션 단위다.
- **로비 == 마을**로 본다.
- 단, **상점방은 인런 내부 공간**이므로 `로비/마을`과 명확히 구분한다.
- **방장 == 호스트**로 본다.
- 문서 표기는 `호스트` 또는 `호스트(방장)` 형태를 권장한다.

</details>

<details>
<summary><strong>7. 무기 로드맵</strong></summary>

- 확장 무기 후보의 최신 기준은 **검 / 망치 / 활**이다.
- 이전 문서에 다른 무기 흔적이 있더라도, 현재 공식 기준은 위 3종으로 관리한다.

</details>

<details>
<summary><strong>8. 무기 해금 / 무기 트리 해금</strong></summary>

- 무기 해금 및 선택 시점은 **마을(= 로비), 즉 런 외부**다.
- 무기 해금 재화는 **기억의 파편(memoryShards)** 으로 통일한다.
- `gold`는 **영속화하지 않으며 인런 재화로 고정**한다.
- 각 무기(검, 망치, 활)는 **각기 다른 해금 트리**를 가진다.
- 예를 들어 일반 검에서 불검, 얼음검, 장검 같은 식으로 **서로 다른 해금 트리 분기**를 가질 수 있다.
- 각 해금 트리의 노드는 **기억의 파편을 일정량 소모해 해금**하는 구조로 본다.
- 한 번 해금한 무기는 이후부터 **런 시작 전에 해금된 무기들 중 하나를 선택**해 던전에 진입할 수 있다.
- 앞으로는 `무기 강화`라는 표현보다 **`무기 해금`, `무기 트리 해금`** 표현을 우선 사용한다.

</details>

## 1-1. 현재 확정 사항

- MVP에서는 **이메일을 사용하지 않는다.**
- 회원가입 및 로그인은 **`loginId + password + nickname`** 을 기준으로 한다.
- `nickname`은 인게임 표시명으로 사용한다.
- 로그인 상태 유지를 위해 토큰 구조는 **access token + refresh token** 을 유지한다.
- `access token`은 **클라이언트 메모리 저장**을 원칙으로 한다.
- `refresh token`은 **클라이언트 영구 저장소 보관**을 전제로 한다.
- 로그아웃 시에는 **refresh token을 무효화**한다.
- 로그아웃 없이 종료하면 **refresh token을 유지**하여 재로그인 없이 접속할 수 있다.

## 1-2. 현재 미정 / 논의 필요

### provider 1단계 명칭
- 현재 인증 구조에서 `provider` 개념 자체는 유지할 수 있다.
- 다만 이메일을 사용하지 않으므로, 1단계 provider를 `EMAIL`로 두는 것은 맞지 않는다.
- 후보 예시:
  - `LOCAL`
  - `BASIC`
  - `LOGIN_ID`

### 왜 논의가 필요한가
- `user_auth_identities` 설계와 연결된다.
- 추후 **Steam 연동** 방식과도 연결된다.
- 지금 당장 MVP를 막는 요소는 아니지만, **백엔드 스키마 확정 전에는 정리 필요**하다.

## 1-3. 현재 권장 표현

- `간단 계정 로그인`
- `loginId 기반 로그인`

## 1-4. 비권장 표현

- `이메일 인증 기반 로그인`
- `EMAIL provider`를 현재 MVP 1단계 명칭처럼 사용하는 표현

<details>
<summary><strong>2. 재화 구조</strong></summary>

## 2-1. 현재 확정 사항

### memoryShards
- `memoryShards`는 **영구 재화**다.
- 런 종료 후 정산되어 플레이어 영구 성장에 반영된다.
- 기억의 조각 해금, 기억의 파편 등 **런 외부 시스템**과 연결된다.

### gold
- `gold`는 현재 기준 **인런 재화**다.
- 런 내부 상점 구매 등 인런에서 사용한다.
- 기본 해석은 **런 종료 후 소멸**이다.

## 2-2. 추가 확정 사항

### 무기 해금 재화
- 무기 해금 재화는 **기억의 파편(memoryShards)** 으로 통일한다.
- 무기 트리의 각 해금 노드도 **기억의 파편을 소모**해 열 수 있다.
- 따라서 플레이어 영구 재화 구조의 중심은 **기억의 파편**이다.

### gold 사용 범위
- `gold`는 **인런 재화로 고정**한다.
- 무기 해금/선택, 무기 트리 해금, 메타 성장에는 사용하지 않는다.
- 즉 `gold`는 런 내부 상점 및 인런 선택 구조에만 연결된다.

## 2-3. 현재 권장 표현

- `인런 gold`
- `영구 재화(memoryShards)`
- `무기 해금 재화 = 기억의 파편`

</details>

<details>
<summary><strong>3. 메타 성장</strong></summary>

## 3-1. 현재 확정 사항

### 재능
- `재능`은 **런 외부 시스템**이다.
- 언제든 **초기화 및 재분배 가능**한 스탯 분배 시스템이다.
- 플레이어가 원할 때 다시 스탯을 분배할 수 있다는 점이 핵심이다.

### 기억의 파편
- `기억의 파편`는 **런 외부 시스템**이다.
- `memoryShards`를 소모하는 **영구 강화 수단**이다.
- 누적형 성장이라는 점이 핵심이다.

## 3-2. 최종 구분

- **재능** = 재분배 가능한 외부 스탯 분배
- **기억의 파편** = `memoryShards`를 쓰는 영구 강화

## 3-3. 왜 이 구분이 중요한가

이 둘을 섞으면 아래가 꼬인다.
- 메타 성장 UI
- Talent API
- memoryShards 사용처
- 저장 구조
- 기억의 조각 효과와의 연결

## 3-4. 현재 권장 표현

- `재능 분배`
- `기억의 파편`

## 3-5. 비권장 표현

- 재능과 기억의 파편를 같은 시스템처럼 쓰는 표현
- 기억의 파편을 재능 포인트처럼 설명하는 표현

</details>

## 4-4. 현재 권장 문장

> 인런 실시간 상태는 유니티 런타임이 authoritative 하게 관리하고, 정산 및 저장은 백엔드가 담당한다.

- `호스트`
또는
- `호스트(방장)`
형태로 통합 관리하는 것이 적절하다.

## 6-5. 현재 권장 표현

<details>
<summary><strong>9. 무기 로드맵 / 무기 해금</strong></summary>

## 9-1. 현재 최신 기준

확장 무기 후보는
- **검**
- **망치**
- **활**
기준으로 관리한다.

## 9-2. 무기 해금 구조

- 무기 해금 및 선택 시점은 **마을(= 로비), 즉 런 외부**다.
- 각 무기는 **각기 다른 해금 트리**를 가진다.
- 각 해금 트리의 노드는 **기억의 파편(memoryShards)** 을 소모해 해금한다.
- 한 번 해금한 무기는 이후부터 **런 시작 전에 해금된 무기들 중 하나를 선택**해 던전에 진입할 수 있다.
- 따라서 무기 관련 메타 성장은 **런 외부 해금 구조**로 본다.

## 9-3. 비고

- 이전 문서들에는 다른 무기 흔적도 있었지만, 현재 공식 기준으로는 위 3종을 최신 기준으로 본다.
- 앞으로는 `무기 강화`보다 **`무기 해금`, `무기 트리 해금`** 표현을 우선 사용한다.

## 9-4. 현재 권장 표현

- `확장 무기 후보: 검 / 망치 / 활`
- `무기 해금`
- `무기 트리 해금`

</details>
