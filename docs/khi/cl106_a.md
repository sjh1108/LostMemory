## 🔥 핵심 발견 (plan 에 없던 것)

### 1. Update() 미호출 진단 — Play 모드 미진입

검증 시나리오 2 후반 (3 초 자동 만료) 에서 **5 초 이상 대기해도 만료 로그가 안 뜨는** 현상 발생. 코드 버그 의심 → 임시 디버그 로그 1 줄 추가 (`Update()` 진입부 매 프레임 출력) → **`[DBG] tick:` 로그가 0 회 출력**.

**원인**: ContextMenu 디버그 메뉴 (`Add / Log / Clear`) 는 Edit Mode 에서도 *그냥 메서드 호출* 이라 작동하지만, MonoBehaviour 의 `Update()` 는 **Play Mode 에서만** 호출. 검증자가 Edit Mode 에서 검증 진행 → 영구/합산/Clear 는 모두 통과 (Update 의존 없음) → 임시 만료만 실패.

**해결**: ▶ Play 버튼 진입 후 `[DBG] tick: count=1, Time.time=16.13~18.80, scale=1` 정상 출력 + 만료 정상.

**교훈**: 향후 PlayMode 검증 가이드의 첫 항목으로 *"▶ Play 버튼 파랗게 켜져 있는지 확인"* 명시. ContextMenu 직접 호출은 Edit Mode 에서도 *부분 작동* 하므로 헷갈릴 위험 큼.

### 2. Unity 의 새 필드 자동 직렬화는 *Inspector 1 회 열림* 이 트리거

plan 의 `완료된 코드 (참고)` 섹션에서 *"Unity 자동 직렬화 동작: 새 필드 추가 → 기존 18 asset 들이 기본값 (None / 0) 으로 자동 채워짐"* 으로 가정. 실제로는:

- Inspector 에서 .asset 을 *한 번이라도 열어야* dirty 발생 + .asset YAML 에 새 4 필드 직렬화
- 안 열면 .asset 의 마지막 줄이 `_icon: {fileID: 0}` 에서 끝남. 메모리 default 는 부여되지만 디스크 저장 안 됨
- 본 CL 의 비-MVP 3 개 (`광전사의문장`, `시공의파편`, `랜덤박스`) 는 정확히 이 케이스. 효과상 None / 0 동등이라 무해, but *완전 직렬화* 의도였다면 한 번씩 클릭 필요

**교훈**: 후속 CL 에서 RelicData asset 의 새 필드 추가 시 *전수 클릭 + Reimport* 단계 plan 에 명시.

### 3. 큰회복약 검증 누락 → git status 로 발견

asset 18 개 입력 직후 `git status` 의 `M` 표시가 14 개만 (예상 12 실효 + 명시 None 3 = 15 ≠ 실제 14) → 단일 누락 추적 → **`RelicData_큰회복약.asset` 의 새 4 필드 미직렬화** 발견. Inspector 미저장 (또는 Ctrl+S 누락). 보완 후 정상 직렬화 (`_effectType: 11, _magnitude: 0.5, _duration: 0, _threshold: 0`).

**교훈**: asset 다량 입력 후 `git status` + 변경 파일 수 검증 = 단순하지만 효과적인 누락 탐지.
