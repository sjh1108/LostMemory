# CL-009 검 1~3타 구현 계획

## 목적

`CL-009 검 1~3타 기본 공격 구현`의 방향을 정리한다.

현재 `test_khi`에서 TopDown Engine의 `ComboWeapon`과 `MeleeWeapon`으로 검 3타를 실험했지만, 좌우 공격은 어느 정도 맞는 반면 위/아래 공격과 무기 뒤집힘, 히트박스 방향이 계속 꼬이는 문제가 확인됐다.

따라서 TDE 무기 프리팹 기반 튜닝은 프로토타입으로 남기고, MVP 검 공격은 프로젝트 전용 콤보/히트박스 코드로 구현한다.

## 결정 사항

- 공격 방향은 4방향으로 사용한다.
- 공격 방향은 공격 시작 순간의 마우스 위치를 기준으로 고정한다.
- 1타와 2타는 빠른 전방 사선 베기다.
- 2타는 1타의 반대 사선 베기이며, 범위는 1타와 같거나 약간 넓게 시작한다.
- 3타는 넓은 전방 마무리 공격이다.
- 공격 중 이동은 우선 허용한다.
- 콤보 입력 유예 시간은 우선 짧게 두고 테스트로 조정한다.
- 유물/세트 효과용 3타 마무리 이벤트는 우선 3타가 적에게 명중했을 때 발생시킨다.

## 시작 수치

`docs/10_weapon_design.md`의 검 타이밍 시작값을 우선 사용한다.

| 타수 | 전체 시간 | 선딜 | 판정 지속 | 후딜 |
|---|---:|---:|---:|---:|
| 1타 | `0.20s` | `0.05s` | `0.07s` | `0.08s` |
| 2타 | `0.25s` | `0.06s` | `0.08s` | `0.11s` |
| 3타 | `0.40s` | `0.10s` | `0.12s` | `0.18s` |

피해 계수 시작값도 같은 문서를 따른다.

| 타수 | 피해 계수 | 역할 |
|---|---:|---|
| 1타 | `1.0` | 빠른 연계 시작 |
| 2타 | `1.1` | 연계와 전방 커버 |
| 3타 | `1.5` | 넓은 마무리 공격 |

## 방향과 히트박스 원칙

위/아래/좌/우 공격은 같은 오브젝트를 단순 flip해서 해결하지 않는다.

시각 이펙트는 뒤집거나 회전해서 재사용할 수 있지만, 실제 히트박스는 방향별 데이터로 분리한다.

이유:

- TDE의 캐릭터 flip, 무기 flip, collider offset이 함께 동작하면 좌우 전환에서 판정이 쉽게 꼬인다.
- 위/아래 공격은 좌우 공격을 단순히 뒤집은 모양과 체감이 다르다.
- 기획상 검의 방향감은 몸 애니메이션보다 무기와 슬래시 이펙트가 담당해야 한다.

권장 방식:

- 공격 시작 시 마우스 방향을 4방향으로 양자화한다.
- 타수와 방향을 기준으로 히트박스 offset/size를 선택한다.
- 1타/2타는 방향 기준 반대 사선 느낌을 데이터로 표현한다.
- 3타는 방향 기준 전방 넓은 영역으로 표현한다.

## TDE 사용 범위

사용 유지:

- TDE `Character`
- TDE 이동/카메라 기반 구조
- TDE `Health`
- TDE 피격/사망/피드백 연결 가능 지점

최종 검 공격에서 사용하지 않을 것:

- TDE `ComboWeapon`
- TDE `MeleeWeapon`의 자동 생성 히트박스
- 캐릭터 flip과 무기 flip에 의존하는 공격 방향 처리

원칙:

- TDE 원본은 수정하지 않는다.
- 공격 입력, 콤보, 방향, 판정은 프로젝트 코드에서 관리한다.
- 명중 후 체력 감소는 우선 TDE `Health`에 연결한다.
- 필요해지면 `IKhiDamageable` 같은 어댑터를 두고 TDE `Health`를 감싼다.

## 코드 구조

### `KhiPlayerAim`

- 마우스 위치를 월드 좌표로 변환한다.
- 플레이어 기준 방향 벡터를 계산한다.
- 방향 벡터를 4방향으로 변환한다.
- 공격 시작 시점의 방향을 제공한다.

### `KhiMeleeComboController`

- 공격 입력을 받는다.
- 현재 콤보 타수를 관리한다.
- 공격 시작 순간 방향을 고정한다.
- 선딜, 판정 지속, 후딜 타이밍을 실행한다.
- 1타 -> 2타 -> 3타 순서로 연계한다.
- 콤보 유예 시간이 지나면 1타로 초기화한다.
- 3타 명중 시 유물/세트 효과용 이벤트를 발생시킨다.

### `KhiMeleeAttackData`

- 타수별 피해 계수를 가진다.
- 타수별 선딜, 판정 지속, 후딜을 가진다.
- 방향별 히트박스 offset/size를 가진다.
- 이후 ScriptableObject로 분리할 수 있게 설계한다.

### `KhiMeleeHitbox`

- active 시간 동안만 판정을 켠다.
- 같은 공격에서 같은 대상을 중복 타격하지 않는다.
- 명중 대상의 TDE `Health`에 데미지를 전달한다.
- 명중 결과를 `KhiMeleeComboController`에 돌려준다.

### `KhiAttackVisualPresenter`

- 애니메이션, 슬래시 이펙트, 사운드, 피드백을 담당한다.
- 판정 코드와 분리한다.
- 현재는 없어도 공격이 동작해야 한다.
- 애니메이션이 생기면 `Attack_1`, `Attack_2`, `Attack_3` 트리거를 연결한다.

## 애니메이션 대응

현재는 공격 애니메이션이 없어도 코드 타이밍으로 공격이 동작하게 만든다.

추후 애니메이션이 생기면 아래 방식으로 확장한다.

- 몸체 애니메이션은 `Idle`, `Run`, `Attack_1`, `Attack_2`, `Attack_3`, `Dash`, `Parry`, `Hit`, `Down/Death`를 최소 세트로 본다.
- 공격 시작 시 Animator trigger를 호출한다.
- 초기에는 데미지 판정을 애니메이션 이벤트에 묶지 않는다.
- 필요해지면 애니메이션 이벤트가 hitbox active 타이밍을 호출하도록 바꾼다.

## 이펙트 대응

공격 이펙트는 당장 필수는 아니지만, 구조상 붙일 수 있게 이벤트를 분리한다.

필요 이벤트:

- 공격 시작
- 공격 active 시작
- 공격 active 종료
- 명중
- 3타 명중

이펙트는 방향과 타수를 받아서 재생한다.

기획상 방향 정보는 몸보다 무기와 슬래시 이펙트가 더 많이 담당하므로, 1타/2타/3타 차이는 최종적으로 이펙트에서 강하게 보여줘야 한다.

## 멀티플레이 고려

솔로 플레이에서는 같은 코드를 로컬에서 바로 실행한다.

멀티플레이에서는 판정과 데미지 확정 권한을 호스트로 옮길 수 있게 다음 흐름을 유지한다.

```text
입력 감지
-> 공격 요청 생성
-> 공격 실행
-> 히트 판정
-> 데미지 확정
-> 이펙트 재생
```

솔로 흐름:

```text
로컬 입력
-> 로컬 공격 실행
-> 로컬 히트 판정
-> 로컬 데미지 확정
-> 로컬 이펙트 재생
```

멀티 흐름:

```text
로컬 입력
-> 호스트에게 공격 요청
-> 호스트가 공격 실행/히트 판정/데미지 확정
-> 모든 클라이언트가 공격 이펙트 재생
```

이를 위해 공격 코드는 다음을 피한다.

- 공격 코드 내부에서 `FindObjectOfType`로 전역 매니저를 직접 찾는 구조
- 공격 코드가 룸, 보상, 유물 상태를 직접 수정하는 구조
- 클라이언트가 임의로 적 체력을 확정 감소시키는 구조
- 각 클라이언트가 랜덤 판정을 따로 굴리는 구조
- 입력 처리, 히트 판정, 데미지 확정, 이펙트 재생이 한 메서드에 섞이는 구조

대신 공격 실행 데이터는 명시적으로 남긴다.

```text
comboStep
attackDirection
sequenceId
startTime
attacker
```

나중에 `CL-027 플레이어 방향·행동 상태 동기화`, `CL-028 공격 판정 결과·적 반응 최소 동기화`에서 이 데이터를 기준으로 동기화한다.

## CL-009 완료 기준

- 마우스 기준 4방향 공격이 가능하다.
- 공격 시작 순간 방향이 고정된다.
- 1타, 2타, 3타가 순서대로 발동한다.
- 1타/2타와 3타의 범위 차이가 체감된다.
- 위/아래/좌/우 공격 히트박스가 방향에 맞게 동작한다.
- 공격 중 이동이 가능하다.
- 3타 명중 시 별도 이벤트가 발생한다.
- TDE `Health`를 가진 테스트 대상에게 데미지를 줄 수 있다.

## 후속 작업

- `CL-010`에서 입력 버퍼와 콤보 유예 시간을 다듬는다.
- `CL-011`에서 1타/2타 후 대시 캔슬 가능 여부를 정리한다.
- `CL-012`에서 패링 성공 후 다음 기본 공격 강화 구조를 연결한다.
- `CL-017`에서 히트스톱, 피격 플래시, 3타 피드백을 붙인다.
- `CL-027`, `CL-028`에서 공격 상태와 판정 결과 동기화를 연결한다.

## 구현 결과

2026-04-22 기준 `test_khi`에서 CL-009 1차 구현을 완료했다.

추가된 런타임 코드:

- `KhiPlayerAim`
  - 마우스 위치를 기준으로 플레이어 기준 방향을 계산한다.
  - 공격 시작 순간 방향을 4방향으로 고정할 수 있게 한다.
- `KhiMeleeComboController`
  - 1타, 2타, 3타 순서의 검 콤보를 실행한다.
  - 각 타의 선딜, active, 후딜 시간을 관리한다.
  - 공격 중 이동은 허용한다.
  - 3타 명중 시 `FinisherHit` 이벤트를 발생시킨다.
- `KhiMeleeHitbox`
  - 타수와 방향에 맞는 `Physics2D.OverlapBoxNonAlloc` 판정을 수행한다.
  - 같은 공격에서 같은 `Health`를 중복 타격하지 않는다.
  - TDE `Health.Damage()`를 호출해 데미지를 적용한다.
  - 공격 active 동안 반투명 빨간 박스로 실제 판정 범위를 표시한다.
- `KhiAttackVisualPresenter`
  - 추후 애니메이션 연결을 위해 `Attack_1`, `Attack_2`, `Attack_3` 트리거 호출 지점을 분리했다.
  - 현재는 애니메이션이 없어도 공격 판정이 동작한다.
- `TestKhiDamageDummy`
  - 검 공격 검증용 더미다.
  - 런타임에 `SpriteRenderer`, `BoxCollider2D`, TDE `Health`를 구성한다.
  - 피격 시 노란색 플래시와 체력 로그를 출력한다.
  - 사망 후 자동 부활한다.

변경된 연결:

- `TestKhi_MinimalCharacter2D.prefab`
  - `KhiPlayerAim`, `KhiMeleeHitbox`, `KhiAttackVisualPresenter`, `KhiMeleeComboController`를 연결했다.
  - 기존 TDE `CharacterHandleWeapon.InitialWeapon`은 비웠다.
  - TDE `ComboWeapon/MeleeWeapon`과 커스텀 공격이 동시에 실행되지 않도록 했다.
- `TestKhiSceneBootstrap`
  - `test_khi` 실행 시 상/하/좌/우에 검증용 더미를 자동 생성한다.

## 현재 검증 결과

Unity `test_khi` 플레이 테스트에서 아래 항목을 확인했다.

- 마우스 기준 4방향 공격이 동작한다.
- 공격 시작 순간 방향이 고정된다.
- 오른쪽, 위쪽, 왼쪽, 아래쪽 더미가 각각 명중한다.
- 빨간 반투명 박스가 실제 공격 판정 범위를 보여준다.
- TDE `Health`를 가진 대상에게 데미지가 적용된다.
- 피해 계수 `1.0`, `1.1`, `1.5`가 적용된다.
- 1타/2타보다 3타 범위가 더 넓게 체감된다.
- 더미 체력 로그는 0 아래로 내려가지 않게 표시한다.

검증 로그 예시:

```text
[TestKhiDamageDummy] Hit TestKhi Damage Dummy Right, health=89/100
[TestKhiDamageDummy] Hit TestKhi Damage Dummy Up, health=74/100
[TestKhiDamageDummy] Hit TestKhi Damage Dummy Left, health=85/100
[TestKhiDamageDummy] Hit TestKhi Damage Dummy Down, health=0/100
```

## CL-009 1차 완료 판단

현재 기준으로 `CL-009 검 1~3타 기본 공격 구현`은 기능 기준 1차 완료로 본다.

완료된 항목:

- 4방향 마우스 기준 공격
- 공격 시작 순간 방향 고정
- 1타, 2타, 3타 콤보
- 방향별 히트박스
- TDE `Health` 데미지 연결
- 3타 마무리 이벤트 코드 준비
- 검증용 더미와 판정 범위 표시

완료를 막지 않는 후속 조정:

- 3타 범위와 손맛은 슬래시 이펙트가 붙은 뒤 다시 조정한다.
- 현재 입력 유예는 최소 구현이며, 정교한 입력 버퍼는 `CL-010`에서 다룬다.
- 대시 캔슬은 `CL-011`에서 다룬다.
- 패링 후 다음 공격 강화는 `CL-012`에서 다룬다.
- 히트스톱, 카메라 흔들림, 실전 피격 플래시는 `CL-017` 또는 `CL-067`에서 다룬다.
