## 🔥 핵심 발견 (plan 에 없던 것)

### KhiPlayerStateAggregator 의 Defeated 타이밍 버그

검증 시나리오 B (Player 사망 → RunFailed) 에서 RunFailed 가 영영 떨어지지 않는 현상 발생. 진단 결과:

**시퀀스**:
1. `KhiDownController.HandleHealthHit` (DefaultExecutionOrder=70) → `EnterDefeatedSolo` → `ExecuteDefeat` → `Health.Kill` → **GameObject SetActive(false)** (같은 프레임)
2. `KhiPlayerStateAggregator.Update` (DefaultExecutionOrder=200) → GameObject 가 이미 inactive → Update 실행 안 됨
3. → **`StateChanged(Hurt, Defeated)` 가 영영 발행되지 않음**
4. → RunManager 가 신호 못 받음 → RunFailed 안 일어남

결정적 증거 (Console 로그):
```
[KhiDown] Solo lethal -> Defeated t=4.680
Coroutine couldn't be started because the the game object 'TestKhi_MinimalCharacter2D' is inactive!
```
↑ KhiDownController 는 Defeated 도달, 그러나 같은 프레임에 GameObject 비활성화.

`KhiPlayerStateAggregator.cs` line 12-13 주석도 이 케이스를 *경고* 하고 있었음 ("Defeated 시 Aggregator의 OnDisable도 호출됨"). plan 의 위험 1번에서 Aggregator 경로로 정한 게 이 타이밍을 못 잡아냄.

### 영향 / 정책 변경

- **CL-048 코드 수정**: `RunManager` 가 `KhiDownController.DefeatedByTimeout` / `DefeatedSolo` 를 *직접* 구독. 이 이벤트들은 GameObject 비활성화 *직전* (Health.Kill 호출 전) 에 발행되므로 신뢰 가능
- **plan 의 위험 1번 갱신**: "KhiPlayerStateAggregator 구독" → "KhiDownController 직접 구독" 으로 정책 변경. CL-014 도입 시 부활 deadline 로직은 *KhiDownController 측* 에 추가
- **KhiPlayerStateAggregator 자체의 한계 명시**: 본 Aggregator 는 *Player GameObject 가 살아있는 동안* 에만 신뢰 가능한 폴링 기반 single-source-of-truth. *생명주기 종료* 신호로는 부적합. 향후 다른 시스템도 Defeated 가 필요하면 KhiDownController 이벤트 사용 권장
