# 클라이언트 세부 계획

## 문서 목적

`docs/12_development_plan.md`의 상위 일정과 역할 분담을 기준으로, 클라이언트 팀이 바로 작업을 시작할 수 있도록 실행 단위까지 세분화한다.  
이 문서는 Unity 클라이언트 구현, 온라인 코옵 연결, 전투/UI/아트 통합, 백엔드 연동 시점을 클라이언트 관점에서 정리한 문서다.

## 일정 기준

- 기본 일정은 `0~8단계, 총 9주`를 기준으로 한다
- 상위 계획 문서에는 `8주 기준` 표현이 있으나, 실제 단계 표는 `0단계~8단계`로 구성되어 있으므로 클라이언트 상세 계획은 `9주 기본안`으로 정리한다
- 일정이 8주로 줄어들 경우에는 `5단계`와 `6단계`를 병합하고, `8단계 버퍼`를 최소화하는 압축안을 적용한다

## 목표

- 검 1종 기준 전투 손맛을 먼저 완성한다
- `NGO + Unity Transport + Relay + Multiplayer Services SDK` 기반 2인 온라인 코옵을 안정화한다
- `전투 -> 보상 3택 -> 상점 -> 전투 -> 보스 -> 결과` 흐름을 2인 기준으로 끝까지 플레이 가능하게 만든다
- 임시 에셋으로 먼저 검증하고, 후반에 UI/도트/VFX를 교체한다

## 비목표

- 4인 안정화
- 자동 매칭
- 재접속 복구
- 호스트 마이그레이션
- 복수 무기 완성
- 고도화된 메타 성장

## 클라이언트 작업 원칙

- 전투 판정, 적 스폰, 방 클리어, 보상 선택 확정, 보스 페이즈 전환은 호스트 기준으로 처리한다
- 클라이언트는 입력과 표현을 담당하되, 핵심 진행 상태는 호스트가 결정한다
- `TopDown Engine` 원본 폴더는 직접 수정하지 않고 상속과 조합으로 확장한다
- 전투 감각과 네트워크 안정성 검증이 끝나기 전에는 콘텐츠 양을 늘리지 않는다
- 초반 2주는 반드시 임시 UI와 임시 에셋으로 속도를 확보한다
- 아트 품질보다 판독성을 우선한다
- 데이터는 가능하면 `ScriptableObject` 또는 테이블 기반으로 관리하고, 전투 수치를 코드에 하드코딩하지 않는다
- 파티 플레이에서 스토리 진행 기준은 `파티원 중 가장 스토리가 덜 진행된 플레이어`에 맞춘다
- 상위 진행도 플레이어가 낮은 진행도 플레이어의 스토리 해금 상태를 건너뛰게 만들지 않는다

## 선확정 항목

아래 항목은 현재 기준 확정값이다.

| 항목 | 확정안 | 담당 |
|---|---|---|
| Unity 버전 | `Unity 6.3` (`6000.3.13f1`) | 클라이언트 리드 |
| 렌더 파이프라인 | `URP` | 클라이언트 리드 |
| 입력 방식 | `WASD 이동 + 마우스 조준` | 클라이언트 1 |
| 패링 규칙 | MVP는 `방향 없는 타이밍 패링` | 클라이언트 1 |
| 대시 규칙 | `짧은 무적 포함 대시`를 기본안으로 확정하고 수치만 조정 | 클라이언트 1 |
| 타일 기준 | `64x64`, 확정 후 변경 금지 | 클라이언트 3 |
| 세션 흐름 | `호스트 생성 -> 코드 표시 -> 코드 입력 참가` | 클라이언트 리드 + 백엔드 |
| 스토리 동기화 기준 | `파티원 중 가장 스토리가 덜 진행된 플레이어` 기준 | 클라이언트 리드 + 클라이언트 2 |
| 네트워크 권한 | 호스트가 방 진행과 결과를 최종 확정 | 클라이언트 리드 + 클라이언트 2 |
| TDE 확장 방식 | 원본 수정 금지, `client/LostMemory/Assets/Game` 하위 확장 | 클라이언트 리드 |
| 데이터 포맷 | 전투/유물/적 수치는 데이터 에셋화 | 클라이언트 2 + 클라이언트 3 |

## 권장 클라이언트 구조

- `client/LostMemory/Assets/Game/Core`: 공통 유틸, 상수, 초기화
- `client/LostMemory/Assets/Game/Combat`: 플레이어, 무기, 피격, 패링, 대시, 카메라
- `client/LostMemory/Assets/Game/Networking`: 세션, Relay 접속, NetworkObject, RPC, 상태 동기화
- `client/LostMemory/Assets/Game/Gameplay`: 적, 방 진행, 룸 매니저, 보상, 상점, 보스, 런 상태
- `client/LostMemory/Assets/Game/UI`: HUD, 로비, 코드 입력, 결과 화면, 상점/보상 UI
- `client/LostMemory/Assets/Game/Data`: 무기, 유물, 적, 보상, 밸런스 데이터
- `client/LostMemory/Assets/Game/ArtTemp`: 임시 스프라이트, 임시 VFX, 임시 UI
- `client/LostMemory/Assets/Game/Scenes`: 부트, 전투 테스트, 네트워크 테스트, 로비, 런 메인, 보스 테스트

## 담당 분배

### 클라이언트 1

- 전투 코어 주담당
- 입력, 조준, 카메라, 플레이어 상태 담당
- TDE 캐릭터/어빌리티 구조 분석 담당
- 패링, 대시, 검 3타, 타격감 품질 책임
- 전투 관련 네트워크 동기화 규칙 리뷰 참여

### 클라이언트 2

- 적 AI, 방 진행, 룸 매니저, 보스 주담당
- 진행 상태와 호스트 권한 구조 설계 담당
- 적/방/보상/상점/보스의 네트워크 동기화 책임
- 런 상태 머신과 예외 흐름 정리 담당

### 클라이언트 3

- HUD, 로비, 결과, 상점/보상 UI 주담당
- 도트 아트 리드와 에셋 통합 담당
- 데이터 에셋 정리와 UI 데이터 바인딩 담당
- 임시 UI -> 1차 아트 UI 교체 흐름 책임

## 협업 규칙

- 클라이언트 1이 전투 프리팹과 플레이어 상태를 변경하면, 클라이언트 2는 네트워크 상태와 진행 규칙 영향도를 같은 날 확인한다
- 클라이언트 2가 적/방 진행 규칙을 변경하면, 클라이언트 3은 보상/UI/진행 표시 영향도를 같은 날 확인한다
- 클라이언트 3이 UI 구조를 변경하면, 클라이언트 1과 2는 입력 흐름과 네트워크 오류 처리 노출 여부를 확인한다
- 매주 1회 전원 플레이 테스트 빌드를 만든다
- 매주 종료 시 다음 주 절대 미루지 않을 작업 3개만 남긴다

## 단계별 세부 계획

### 0단계: 프리프로덕션

기간:
- 1주

핵심 목표:
- 클라이언트 개발 기반과 기술 결정을 끝낸다

클라이언트 1:
- Unity 프로젝트 생성
- 입력 시스템 선택 및 기본 조작 골격 구현
- 검 3타, 대시, 패링의 파라미터 시트 초안 작성
- TDE 캐릭터/어빌리티 확장 포인트 조사

클라이언트 2:
- `NGO`, `Unity Transport`, `Relay`, `Multiplayer Services SDK`, `Multiplayer Play Mode` 설치 및 버전 고정
- `NetworkManager` 테스트 씬 구성
- 호스트 기준 진행 구조 초안 작성
- 적/방/보상/보스의 권한 경계 초안 정리
- 파티 스토리 진행도 동기화 규칙 초안 작성

클라이언트 3:
- 임시 HUD와 로비 와이어프레임 제작
- 타일 크기, 해상도, 팔레트, 폰트 톤의 1차 기준안 작성
- 유물/상점/보상 데이터 구조 초안 작성
- 임시 에셋 세트 준비

공동 산출물:
- Unity 프로젝트 초기 세팅
- 클라이언트 폴더 구조
- 네트워크 테스트 씬
- 전투 파라미터 시트 초안
- 유물 데이터 시트 초안
- 임시 UI 와이어프레임
- 파티 스토리 동기화 정책 초안

완료 기준:
- 팀이 동일한 입력 구조와 조작 기준을 공유한다
- 네트워크 스택과 세션 흐름이 확정된다
- TDE 원본 수정 없이 구현할 범위가 정리된다
- 클라이언트와 백엔드의 역할 경계가 합의된다

### 1단계: 전투 코어 프로토타입

기간:
- 1주

핵심 목표:
- 1인 전투 손맛과 2인 접속 최소 흐름을 동시에 검증한다

클라이언트 1:
- 이동, 검 3타, 대시, 패링, 피격, 다운 기본 구현
- 카메라와 히트스톱, 피격 플래시, 패링 성공 피드백 초안 구현
- 공격 입력 버퍼와 연계 규칙 구현

클라이언트 2:
- 플레이어 프리팹 `NetworkObject` 구성
- 2인 접속과 위치 동기화 테스트
- 더미 적 1종과 기본 타겟 반응 구현
- 호스트 생성/참여 코드 입장 프로토타입 연결

클라이언트 3:
- 임시 HUD 구현
- 참여 코드 입력 UI 구현
- 전투 테스트용 체력바, 쿨타임, 패링 성공 텍스트 또는 아이콘 구현
- 임시 전투 이펙트와 슬래시 이미지 연결

공동 산출물:
- 회색 박스 전투 테스트 맵
- 1인 전투 테스트 빌드
- 2인 접속 및 이동 동기화 테스트 씬
- 전투 감각 피드백 체크리스트

완료 기준:
- 5분 이상 단독 전투 테스트 가능
- 검 1타, 2타, 3타 차이가 체감된다
- 참여 코드 입력만으로 2인 접속 가능
- 패링과 대시가 쓸 이유가 있다

### 2단계: 코옵 베이스라인

기간:
- 1주

핵심 목표:
- 전투 핵심 액션을 2인 기준으로 깨지지 않게 만든다

클라이언트 1:
- 공격, 패링, 대시 타이밍과 로컬 피드백 보강
- 플레이어 상태 머신 정리
- 다운/부활 입력과 표현 구현

클라이언트 2:
- 공격 판정, 적 피격, 다운/부활 동기화 안정화
- `NetworkVariable`과 RPC 사용 기준 문서화
- 호스트 기준 진행 상태 초안 구현
- 입장, 퇴장, 코드 오류, 세션 종료 예외 흐름 정리
- 스토리 진행도 비교 및 파티 기준 진행도 결정 로직 초안 구현

클라이언트 3:
- 세션 상태 표시 UI 구현
- 네트워크 오류 메시지 임시 버전 구현
- 부활, 전멸, 대기 상태 표시 UI 구현
- 보상/상점/결과 화면 와이어프레임 고도화

공동 산출물:
- 2인 전투 테스트 빌드
- 상태 동기화 기준 문서 초안
- 예외 흐름 리스트

완료 기준:
- 2인이 같은 전투 상황을 거의 같은 상태로 본다
- 공격, 피격, 다운 처리에서 치명적 불일치가 줄어든다
- 기본 예외 흐름을 플레이 테스트로 확인했다

### 3단계: 2인 협동 vertical slice

기간:
- 1주

핵심 목표:
- 한 판의 기본 루프를 2인 기준으로 연결한다

클라이언트 1:
- 전투 밸런스 1차 조정
- 유물 효과가 검 3타, 대시, 패링에 반영되도록 플레이어 스탯 연결
- 상점과 보상 선택 이후 스탯 갱신 반영

클라이언트 2:
- 일반 적 3종, 엘리트 1종 구현
- 방 클리어 규칙과 룸 진행 구조 구현
- 보상 3택, 상점 기본 기능, 방 전환 동기화 구현
- 런 상태 머신 1차 구현

클라이언트 3:
- 시작 화면 또는 로비 화면 최소 버전 구현
- 보상 3택 UI, 상점 UI, 룸 진행 UI 구현
- 임시 아이콘과 유물 데이터 표시 연결
- 초대 코드 UX 다듬기

공동 산출물:
- `전투 -> 보상 -> 상점 -> 전투` 루프 빌드
- 룸 진행 동기화 테스트
- 보상/상점 UI 최소 버전

완료 기준:
- 2인 기준 한 판의 뼈대가 이어진다
- 유물 선택이 플레이 감각 차이를 만든다
- 개발자 도움 없이 방 생성/입장이 가능하다

### 4단계: 보스와 런 종료 흐름

기간:
- 1주

핵심 목표:
- 데모에서 보여줄 한 판의 끝을 만든다

클라이언트 1:
- 보스전용 패링, 대시, 피격 타이밍 미세 조정
- 보스전 카메라와 타격감 보정

클라이언트 2:
- 보스 1종과 2페이즈 전환 구현
- 보스방 입장 조건과 런 종료 조건 구현
- 결과 계산 데이터 정리

클라이언트 3:
- 결과 화면 구현
- 보스 경고 UI, 체력바, 페이즈 전환 연출 구현
- 런 종료 후 보상 요약 UI 연결

공동 산출물:
- 2인 기준 1챕터 데모 완주 빌드
- 결과 화면과 런 종료 데이터 구조

완료 기준:
- 보스전이 일반 전투와 다른 패턴 경험을 준다
- 결과 화면에서 핵심 기록을 확인할 수 있다
- 런 종료 흐름이 끊기지 않는다

### 5단계: 콘텐츠 및 연출 보강

기간:
- 1주

핵심 목표:
- 데모 품질에 필요한 유물, 적 연출, 화면 완성도를 올린다

클라이언트 1:
- 전투 피드백 보강
- 유물 세트 효과와 플레이어 능력치 반영 정교화

클라이언트 2:
- 유물 10종 최종 연결
- 이벤트방 0~1종 연결
- 보스 패턴과 적 전조 보강

클라이언트 3:
- 1차 도트 에셋 교체
- HUD와 보상/상점 UI 시각 정리
- 전투 판독성을 해치지 않는 범위에서 이펙트와 아이콘 톤 정리

공동 산출물:
- 플레이 가능한 데모 아트 1차 버전
- 유물 조합 테스트 빌드

완료 기준:
- 유물 태그 조합이 눈에 보이는 차이를 만든다
- 전투 중 판독성이 유지된다
- 임시 화면에서 벗어나 최소 데모 톤이 잡힌다

### 6단계: 서비스 기능 연결

기간:
- 1주

핵심 목표:
- 계정, 저장, 결과 기록을 클라이언트에 붙인다

클라이언트 1:
- 로그인 이후 플레이어 상태 초기화 흐름 연결
- 저장/불러오기 이후 전투 스탯 적용 검증

클라이언트 2:
- 런 결과 저장 시점, 진행 저장 시점, 실패 처리 흐름 연결
- 저장 응답 실패 시 재시도 또는 안전 종료 UX 요구사항 정의

클라이언트 3:
- 로그인 화면, 유저 정보 UI, 최소 메타 화면 구현
- 저장 중, 저장 완료, 저장 실패 메시지 UI 구현
- 결과 화면과 서버 응답 연결
- 파티 스토리 기준 안내 문구 또는 상태 표시 연결

백엔드 의존성:
- 로그인 API
- 유저 정보 조회 API
- 진행 저장 API
- 런 결과 저장 API

공동 산출물:
- 로그인 후 플레이 가능한 빌드
- 결과 저장과 재접속 시 진행 유지 확인

완료 기준:
- 저장 API와 클라이언트 연동이 안정적이다
- 메타 기능이 전투 개발을 망치지 않는 선에서만 붙어 있다

### 7단계: 데모 안정화

기간:
- 1주

핵심 목표:
- 발표 가능한 수준으로 UX와 치명 버그를 정리한다

클라이언트 1:
- 전투 입력, 패링 판정, 카메라, 타격감 최종 보정
- 프레임 드랍 또는 입력 지연 점검

클라이언트 2:
- 네트워크 불일치, 진행 불가, 보스전 중단급 버그 수정
- 예외 상황 로그 보강

클라이언트 3:
- UI 문구 정리
- 최소 튜토리얼 또는 도움말 추가
- 네트워크 오류 메시지와 결과 흐름 정리

공동 산출물:
- 데모 후보 빌드
- QA 체크리스트
- 발표용 플레이 시나리오

완료 기준:
- 신규 플레이어가 짧은 설명만으로 플레이 가능하다
- 데모 중단급 버그가 대부분 제거된다

### 8단계: 버퍼

기간:
- 1주

사용 원칙:
- 신규 기능 추가 금지
- 버그 수정, 연출 보강, 빌드 안정화에만 사용

우선 사용 순서:
- 네트워크 불일치 수정
- 진행 불가 버그 수정
- 전투 피드백 보강
- UI 가독성 보정
- 아트 교체 마무리

## 8주 압축안

- `5단계 콘텐츠 및 연출 보강`과 `6단계 서비스 기능 연결`을 병합한다
- 랭킹 화면과 메타 확장 UI는 제외한다
- 이벤트방은 상황에 따라 제거한다
- `8단계 버퍼`는 2~3일 수준으로 축소한다
- 이 경우에도 `검 전투 손맛`, `2인 코옵 안정성`, `보스 1종`, `결과 저장 최소 기능`은 유지한다

## 클라이언트 주간 운영 방식

- 주 1회 고정 플레이 테스트를 진행한다
- 플레이 테스트 전날까지 각 담당자는 자신의 작업을 병합 가능한 상태로 정리한다
- 테스트 후에는 신규 기능 추가보다 컷 결정과 버그 우선순위 정리가 먼저다
- 이슈 보드는 `Combat`, `Network`, `Progression`, `UI`, `Art`, `Backend-Dependency` 라벨로 분리한다
- 매주 종료 시 다음 주 절대 안 미룰 작업 3개를 확정한다

## 단계별 체크포인트

### M1: 전투 감각 확인

- 검 3타 차별화가 느껴지는가
- 패링 성공이 눈에 띄게 기분 좋은가
- 참여 코드 생성과 입장이 가능한가
- 2인 위치 동기화가 가능한가

### M2: 협동 루프 확인

- 2인이 같은 적, 같은 방 상태를 거의 동일하게 보는가
- 다운/부활 흐름이 어긋나지 않는가
- 전투 이후 보상과 상점으로 자연스럽게 이어지는가

### M3: 데모 구조 확인

- 2인 기준 한 판 완주가 가능한가
- 보상 선택이 전투 스타일 변화를 만드는가
- 보스전과 결과 화면이 끊기지 않는가

### M4: 발표 품질 확인

- 신규 플레이어가 UI를 이해하는가
- 도트 아트와 이펙트가 판독성을 해치지 않는가
- 발표 시나리오 1회 이상 안정적으로 완주 가능한가

## 주요 의존성

- 백엔드가 맡는 로그인, 진행 저장, 결과 저장 API 명세가 5단계 시작 전에는 고정되어야 한다
- Unity 서비스 계정, Relay 환경, 프로젝트 연결 정보는 0단계 종료 전까지 고정되어야 한다
- 타일 크기와 화면 기준 해상도는 2주차 이후 변경하지 않는다
- 유물 1차 목록과 검 1차 수치는 3단계 이전에 얼려야 한다
- 스토리/메타 데이터에서 `계정별 현재 스토리 진행도`를 조회할 수 있어야 파티 기준 동기화가 가능하다

## 클라이언트 기준 컷 순서

2. 랭킹 화면 제거
3. 메타 성장 화면 최소화

- 2인 온라인 접속과 진행 안정성
- 보상 3택의 선택 재미
- 보스 1종과 결과 저장 최소 기능
