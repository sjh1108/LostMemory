# 클라이언트 세부 계획

## 문서 목적

`docs/14_client_jira_story_backlog.md`를 기준으로 클라이언트 작업의 실행 순서, 담당 축, 완료 기준을 정리한다.

이 문서는 Jira 등록용 백로그를 실제 개발 계획으로 해석한 상세 버전이며, 보완 등록분 `CL-103 ~ CL-111`까지 포함해 본다.

## 기준 문서

- 직접 기준: `docs/14_client_jira_story_backlog.md`

- 범위 검증 기준: `docs/12_development_plan.md`

- 메타/스토리 정책 참고: `docs/06_meta_progression.md`

문서 간 표현 차이가 있을 때는 `14_client_jira_story_backlog.md`의 에픽/ID/단계 체계를 우선한다.

다만 프로젝트 전체 MVP 정의와 충돌하지 않도록 `CL-103 ~ CL-111` 보완 등록분을 함께 반영한다.

## 단계 기준

- `1단계. MVP / 핵심 플레이어블`: `CL-001 ~ CL-072` + `CL-103 ~ CL-111`

- `2단계. MVP+ / 완성도 확장`: `CL-073 ~ CL-081`

- `3단계. Post-MVP / 확장·운영 준비`: `CL-082 ~ CL-102`

즉, 현재 클라이언트 상세 계획에서 MVP는 본문 등록분만이 아니라 보완 등록분까지 포함한다.

로그인/저장/결과 저장 최소 기능과 파티 최저 진행도 기준 스토리 동기화는 MVP 완료 조건으로 본다.

## 목표

- 검 1종 기준 전투 감각을 먼저 완성한다.

- `NGO + Unity Transport + Relay + Multiplayer Services SDK` 기반 2인 코옵을 안정화한다.

- `전투 -> 보상 3택 -> 상점 -> 전투 -> 보스 -> 결과` 흐름을 2인 기준으로 끝까지 플레이 가능하게 만든다.

- 임시 UI, 임시 아트, 임시 VFX로 먼저 검증하고 이후 교체한다.

- MVP 범위 안에서 로그인/세션 유지, 진행 저장, 런 결과 저장, 파티 스토리 동기화 최소 기능을 붙인다.

## 비목표

- 4인 안정화

- 자동 매칭

- 복잡한 스토리 분기

- 복수 무기 완성

- 운영 기능 확장

- 랭킹, 시즌형 메타, 대규모 라이브 기능

## 작업 규칙

- `Post-MVP` 항목은 MVP 핵심 플레이어블이 깨지는 상태에서 선행하지 않는다.

- 클라1이 전투 상태나 입력 구조를 바꾸면 클라2는 동기화 영향 범위를 바로 점검한다.

- 클라2가 룸 상태, 적 판정, 보상/상점 흐름을 바꾸면 클라3은 UI 표시와 결과 화면 영향 범위를 바로 점검한다.

- 클라3이 UI 구조를 바꾸면 클라1, 클라2는 입력 흐름과 예외 처리 메시지 노출을 함께 확인한다.

- 매주 최소 1회 2인 통합 플레이 빌드를 만든다.

- `CL-103 ~ CL-111`이 비어 있으면 MVP는 완료된 것으로 보지 않는다.

## 1단계. MVP / 핵심 플레이어블

### 범위

- `CL-001 ~ CL-072`

- `CL-103 ~ CL-111`

### 세부 목표

- 프로젝트 기반 세팅과 공용 규칙을 확정한다.

- 2인 플레이어 전투와 세션 연결을 안정화한다.

- 방 진행, 적 3종, 보상 3택, 상점, 보스 1종, 결과 화면까지 붙인다.

- 최소 로그인/세션 유지, 진행 저장, 런 결과 저장을 붙인다.

- 파티 최저 진행도 기준 스토리 동기화와 안내 UI를 붙인다.

### 권장 실행 순서

| Wave | Jira 범위 | 핵심 산출물 |
|---|---|---|
| Wave 1. 기반 세팅 | `CL-001 ~ CL-006`, `CL-020 ~ CL-021`, `CL-057`, `CL-069 ~ CL-070`, `CL-103` | Unity/패키지 기준, 폴더 구조, TDE 확장 규칙, 네트워크 테스트 씬, 임시 UI 와이어프레임, 유물 데이터 구조 |
| Wave 2. 전투 + 세션 수직 절개 | `CL-007 ~ CL-019`, `CL-022 ~ CL-031`, `CL-058 ~ CL-060`, `CL-066 ~ CL-067` | 이동, 검 1~3타, 대시, 패링, 피격/다운, 코드 참가, 2인 동기화, HUD, 오류 메시지 |
| Wave 3. 런 진행 + 보상/상점 + 보스 | `CL-032 ~ CL-056`, `CL-061 ~ CL-065`, `CL-068`, `CL-071 ~ CL-072`, `CL-104` | 방 진행, 적 3종, 보상 3택, 상점, 보스 1종, 결과 화면, 유물 10종 데이터 |
| Wave 4. MVP 정합성 보완 | `CL-105 ~ CL-111` | 로그인 토큰 저장, 세션 유지, 진행 저장, 런 결과 저장, 저장 실패 UX, 파티 진행도 비교, 스토리 상태 UI |

### 완료 기준

- 2인 기준 `전투 -> 보상 -> 상점 -> 전투 -> 보스 -> 결과` 흐름이 끊기지 않는다.

- 로그인 이후 플레이 가능하고, 진행 저장과 런 결과 저장이 최소 기능으로 동작한다.

- 보스 1종이 일반 전투와 구분되는 패턴 경험을 준다.

- 파티 기준 스토리 동기화 로직이 적용되고, UI에서 최소 상태 안내가 가능하다.

- 임시 아트 상태여도 전투 판독성과 UI 흐름이 데모 가능한 수준이다.

## 2단계. MVP+ / 완성도 확장

### 범위

- `CL-073 ~ CL-081`

### 목표

- 전투 코어를 망가뜨리지 않는 선에서 재능 시스템을 추가한다.

- 로비 동선과 재능 UI를 연결해 반복 플레이 동기를 만든다.

### 핵심 항목

- 재능 타입/최대치/상승량 테이블 정의

- 재능 포인트 분배 로컬 모델

- 재능 초기화/로컬 저장

- 재능 UI 패널, 증감, 저장 연결

- 재능 계산 결과를 런 시작 스탯에 반영

- 재능 시스템 QA와 밸런스 1차 조정

### 착수 조건

- MVP 통합 데모 빌드가 안정적이어야 한다.

- 로그인/저장 최소 기능이 깨지지 않아야 한다.

- 전투, 세션, 룸 진행의 중단급 버그가 정리되어 있어야 한다.

## 3단계. Post-MVP / 확장·운영 준비

### 범위

- `CL-082 ~ CL-102`

### 목표

- 기억 메타, 무기 확장, 서비스 확장, 스토리 상태 UI, 이벤트방 등 확장 기능을 붙인다.

- 에셋 제작 규칙과 사운드 1차 패스를 포함해 운영 준비도를 높인다.

### 세부 묶음

| 묶음 | Jira 범위 |
|---|---|
| 기억/기억의 파편/기억 메타 | `CL-082 ~ CL-089` |
| 무기 확장 | `CL-090` |
| 저장/백엔드 확장 흐름 | `CL-091 ~ CL-096` |
| 스토리 상태 표시 | `CL-097` |
| 이벤트방, 보스 2페이즈 확장 | `CL-098 ~ CL-100` |
| 사운드/에셋 규칙 | `CL-101 ~ CL-102` |

### 유의사항

- 이 단계의 항목은 MVP를 대체하지 않는다.

- `CL-091 ~ CL-096`과 보완 등록분 `CL-105 ~ CL-108`은 범위를 다르게 본다.

- 보완 등록분은 MVP 최소 동작 버전이고, Post-MVP 저장 항목은 확장/정리 버전이다.

## 주요 의존성

- 백엔드의 로그인, 진행 저장, 런 결과 저장 API 명세가 MVP 중반 전에 고정되어야 한다.

- Unity 서비스 계정, Relay 환경, 프로젝트 연결 정보가 초반에 고정되어야 한다.

- 유물 1차 목록과 적/보스 수치 초안이 MVP 후반 전에는 확정되어야 한다.

- 파티 기준 스토리 진행도 조회용 데이터 모델이 백엔드/클라이언트 간 합의되어야 한다.

## 주간 운영 방식

- 주 1회 고정 2인 통합 플레이 테스트를 진행한다.

- 테스트 전날까지 각 담당자는 자신의 작업을 병합 가능한 상태로 정리한다.

- 테스트 후에는 신규 기능 추가보다 결정과 버그 우선순위 정리를 먼저 한다.

- Jira 보드는 `Combat`, `Network`, `Run`, `UI`, `Art`, `Service`, `StorySync` 라벨로 나눠 관리한다.

- 다음 주로 미루는 작업은 최대 3개까지만 허용한다.
